# 代码分析方法

> 供 codebase-book 阶段 2 使用。

## 分析顺序

先建立运行路线，再按路线和依赖顺序分析模块。不按目录树逐个分析。

### 1. 运行路线

追踪一条端到端主流程：输入从哪进入 → 经过哪些函数 → 产生什么输出。写入 `{RUN}/codebase-map.md`。

必须包含：
- 入口命令和启动方式
- 主流程时序（有 file:line 证据）
- 关键数据结构、状态变量
- 失败路径和降级策略

### 2. 模块分析

按优先级分析：入口 → 主流程 → 核心算法 → 状态/副作用 → 基础设施。

每个模块写入 `{RUN}/analysis/{module}.md`，聚焦：

**接口与行为**
- 公共函数/类的签名、参数语义、返回值
- 核心逻辑的控制流和数据流
- 错误路径和边界条件

**设计决策**
- 为什么选择这种数据结构/算法/模式
- 替代方案和权衡
- 代码注释中的设计意图（无注释则标注 V4 推断）

**关键算法**
- 核心思想和复杂度
- 关键参数如何影响结果
- 在本项目中的具体使用方式

**隐含知识**
- 理解这段代码需要的语言特性、框架机制、算法理论
- 标注每个知识点将在何处讲透

每个断言标注 file:line 和验证等级。

### 3. 防止流水账

不要：每个函数一小节的机械目录、对 import 和常量的逐行解释、没有设计含义的调用链复述。

要：提炼核心执行路径、关键抽象、设计取舍。分析不是章节草稿——分析提炼"为什么"和"怎么工作"，章节据此写作。

## 大型代码库

源文件 > 30 个时，按模块分组（每组 5-8 个相关文件）分批分析。每组的分析产出是独立的 `{RUN}/analysis/{module}.md`。
