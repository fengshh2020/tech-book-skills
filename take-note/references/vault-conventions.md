# 库约定（归位 / frontmatter / 骨架 / callout / 双链）

take-note 写库的查阅表——**下笔前读一次**，写时对照。库根解析与笔记质量在 `SKILL.md`；铁律见 `../../shared/writing-core.md`。

## 库结构（在 `$KB_ROOT` 下）

```
$KB_ROOT/
├── 00_首页.md          ← 全库入口
├── 文档库/             ← 书籍/长文档（每本一文件夹 + 00_MOC）
├── 项目-{名}/          ← 每项目自包含：{项目名}.md 作 MOC + 调试/方案/设计 子目录
├── 系统配置/           ← 跨项目复用的工具链/环境配置（扁平，type: config）
└── wiki/               ← 可复利知识库（opt-in，见 llm-wiki.md）
```

任何笔记链回所属 MOC + `00_首页`，不孤立。

## 归位约定

| | 笔记（note） | 书籍/文档（book） | 技术方案（proposal） |
|---|---|---|---|
| 归位 | `项目-{名}/{调试\|方案\|设计}/` 或 `系统配置/` | `文档库/{书名}/` | `项目-{名}/方案/` |
| type | `debug`/`plan`/`config`/`read`/`design` | `moc`（总目录）+ `book`（章节） | `proposal` |

**归位三问**：① 跨项目复用的工具链/环境配置？→ `系统配置/`。② 哪个项目？→ `项目-{名}/`，子目录对齐该项目已有目录。③ 项目还没夹？→ 问用户新建还是归现有。

**文件名**：中文主题词 + 必要英文术语，空格分隔，带论点与可搜索关键词；无日期前缀（日期在 frontmatter）。多页连续主题用 `数字_标题.md` + `prev`/`next`。

## frontmatter（六字段必填）

```yaml
---
title: "{标题，与文件名、H1 一致}"
type: {moc | design | debug | plan | config | read | proposal}
project: {现有项目名 | 系统配置 | 知识库 | {新项目名}}
date: YYYY-MM-DD
status: {active | draft | archived}
tags:
  - {platform}     # jetson-agx-orin（硬件相关时）
  - {tech}         # tensorrt, pytorch（核心技术）
  - {topic}        # deployment, conversion（主题）
---
```

`tags` 3-8 个扁平、不要层级。可选：`platform`、`source`、`prev`/`next`/`book`（仅多页系列/书式笔记）。

## 正文骨架（按 type 裁剪，不是每节都用）

```markdown
# {标题}

> {YYYY-MM-DD} · {项目或场景} · {一句话：记什么、为什么记}

> [!important] 结论 / TL;DR
> {最重要的答案/命令/论点，1-3 句。}

## 背景 / 环境基线 / 问题描述
{环境基线用表格（设备/版本/配置）。}

## 坑 N：{坑标题}（仅踩坑/调试类）
> [!warning] 现象：{报错原样引用}
> **根因**：{为什么；复杂根因用 5-Why 链}
> **解决**：`{命令}` → `# 预期输出: {...}`

## 关联笔记
- [[{相关笔记}]] — {一句话关系}
- [[{待创建}]]（待创建）

---
📍 所属项目：[[{项目MOC 或 00_首页}]] · 知识库入口 [[00_首页]]
```

**硬约定**：单个 `# H1`（同文件名）、不跳级；shell/dockerfile/python 块下加 `# 预期输出: ...` 让读者一眼判断是否跑通；引用"为什么"时指向源码行或源链接；**面包屑页脚必加**（`系统配置/` 无项目 MOC，写 `📍 知识库入口 [[00_首页]]`）。

## Callout 语义（库固定）

| 用途 | Callout |
|---|---|
| 陷阱/坑/反例 | `> [!warning]` |
| 补充说明 | `> [!info]` / `> [!tip]` |
| 最重要结论 | `> [!important]` |
| 推断/未实测/待验证（**最重要——别把假设写成结论**） | `> [!caution]`（标"推断/待验证"） |
| 已验证/确认可用 | `> [!success]` |

## 双链（笔记是网络节点）

1. **结构回链**：面包屑页脚指向项目 MOC + `00_首页`。
2. **主题互链**：`## 关联笔记` 区链 1-2 条相关笔记并注明关系；`[[待创建]]（待创建）` 留给应存在但还没的。新笔记回头更新它引用到的项目 MOC（笔记地图加一行），让双链闭环。`文档库/` 下每本书的 `00_MOC` 是书总目录、与项目 MOC 不同（别链错）。
