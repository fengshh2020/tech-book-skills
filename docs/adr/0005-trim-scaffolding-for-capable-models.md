# 0005 — 为强模型裁剪防御性脚手架

本库历史上按"模型会偷懒、会伪造 Gate、会缩减内容"的假设设计：铁律被逐字重复 3 次；防懈怠机制 / 防跳步检查 / 失败模式目录 / 反合理化表反复复述同样三条理念；外加 Gate 降级、错误恢复、STOP 硬停、progress.md 仪式，以及两份强制执行的 `workflow.py`（1246 + 346 行）。结果是 ~40-50% 的篇幅是防御性脚手架，反复复述把真正的领域信号埋没在噪声里。

2026-07-13：目标模型能力分级上调。强模型能对照正文自检、不需要 python 状态机强制每一步，也不需要"你想偷懒时会这么想"的枚举式劝阻。本 ADR 记录由此而来的结构性裁剪。

## 考虑过的方案
- **保守去重（只合并逐字重复）**：零风险，但 ~70% 的复述（同一理念换三种说法）仍留在库里，收益有限。
- **深度裁剪（选这个）**：铁律只留 1 处、失败模式压成 5 行、删 Gate 降级/错误恢复/反合理化/STOP 的逐项枚举与两份 `workflow.py`；保留全部领域实质规则（翻译 1:1、整合 L1-L4、Coverage Guardian、证据 V1-V4、叙事写作、md-authoring、发现格式）+ builder + 校验脚本。
- **裁剪 + 合并 skill**：把 take-note 并入 generate-book。否决：两者目标不同（Obsidian 库 vs 工作区），合并会破坏 `/take-note` 路由与 Obsidian 专项约定。改为"共享 Writing Core、保留 3 触发器"。

## 选深度裁剪的理由
强模型把脚手架当噪声而非护栏——枚举式防护反而稀释信号、挤占上下文。把纪律收敛到 `shared/writing-core.md` 唯一源（铁律 + 原则 + 证据 + 失败模式 5 行），每个 skill 只引用不重述。Gate 从"python 强制状态机"退化为"正文自检清单"：强模型能诚实自检，校验脚本（`validate_*.{sh,py}`）仍提供机械兜底。

## 关键约束
- **保留机械校验**：`build_html.py`、`validate_tech.py`、`validate_terms.py`、`validate_code.sh`、`check_coverage.sh` 是真 builder / 真校验，不删；它们是客观兜底，与"是否信任模型自检"无关。
- **保留触发器路由**：3 个 skill 的 `description` 触发短语不动，避免破坏用户调用习惯；泛化通过扩 generate-book 的能力轴（输入 × 形态）+ take-note 引用 Writing Core 实现。
- **失败模式不归零**：5 行版保留在 Writing Core——"声称读过但没读 / 产出比源浅 / 没跑校验就标通过"这三类是真实风险，强模型也会犯，值得一句提醒。
- 回退路径：若自检质量下降，可在 mode 文件里为单个高风险阶段重新加回显式 checklist，而不必恢复整套脚手架。
