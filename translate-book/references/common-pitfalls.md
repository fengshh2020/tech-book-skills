# 翻译常见陷阱

从实际翻译和审阅反馈中总结的高频错误模式。翻译每章后对照此清单自检。

## 结构陷阱

| 陷阱 | 表现 | 修正 |
|------|------|------|
| 段落合并 | 将原文 2-3 段合并为 1 段 | 严格一一对应 |
| 锚点丢失 | 原文有 `id="item-N"` 翻译后缺失 | 逐个核对 |
| 列表塌缩 | 有序列表变成纯文本段落 | 保留 `<ol>/<ul>` 结构 |
| 嵌套层级错误 | `<li>` 内的 `<p>` 被提升到列表外 | 保持原文嵌套 |
| 代码块标记丢失 | `<pre><code>` 变成普通文本 | 标记所有代码块 |

**正反例 — 段落合并**：

❌ 合并：
```html
<p>生成器是一种特殊的迭代器。它通过 yield 语句暂停执行，
在需要时恢复。这使得我们可以处理无限序列。</p>
```

✅ 保持原文结构：
```html
<p>生成器是一种特殊的迭代器。</p>
<p>它通过 yield 语句暂停执行，在需要时恢复。</p>
<p>这使得我们可以处理无限序列。</p>
```

## 术语陷阱

| 陷阱 | 表现 | 修正 |
|------|------|------|
| 同词异译 | 同一术语前后译法不同 | 全文统一 |
| 括注遗漏 | 首次出现未括注英文 | 首现必括注 |
| 过度翻译 | stack 译为"知识栈"而非"堆栈" | 使用技术通用译法 |
| 生造术语 | 自创中文术语 | 使用社区约定译法 |

**正反例 — 同词异译**：

❌ 同一术语两种译法：
> 第 3 章介绍了**装饰器**（decorator）的用法……第 7 章深入探讨了**修饰器**的高级技巧。

✅ 全文统一：
> 第 3 章介绍了**装饰器**（decorator）的用法……第 7 章深入探讨了**装饰器**的高级技巧。

**正反例 — 括注遗漏**：

❌ 首次出现未括注：
> 上下文管理器可以自动管理资源的获取和释放。

✅ 首现括注：
> 上下文管理器（context manager）可以自动管理资源的获取和释放。

## 风格陷阱

| 陷阱 | 表现 | 修正 |
|------|------|------|
| 翻译腔 | "它是一个...的东西" | 重写为自然中文 |
| 被动语态泛滥 | "被用来做" | 改为主动："用于做" |
| 长定语堆叠 | "一个用于处理数据的可以被重用的对象" | 拆短句或前置定义 |
| 英文句式照搬 | 保留英文的定语从句结构 | 调整为中文语序 |

**正反例 — 翻译腔**：

❌ 翻译腔：
> 它是一个被用来将函数作为参数传递给另一个函数的机制。

✅ 自然中文：
> 高阶函数可以接收函数作为参数，也可以返回函数。

**正反例 — 被动语态**：

❌ 被动泛滥：
> 这个方法被用来创建对象。参数被传递给构造函数。返回值被存储在变量中。

✅ 主动语态：
> 这个方法用于创建对象。构造函数接收参数，返回值存入变量。

**正反例 — 长定语**：

❌ 长定语堆叠：
> 这是一个用于在多个协程之间进行协作式调度的基于事件循环的异步执行机制。

✅ 拆分：
> 异步执行机制基于事件循环，在多个协程之间进行协作式调度。

## 格式陷阱

| 陷阱 | 表现 | 修正 |
|------|------|------|
| 行内代码遗漏 | 原文 `` `word` `` 翻译后丢失反引号 | 保留行内代码标记 |
| 加粗丢失 | 原文 `<strong>` 翻译后变普通文字 | 保留所有强调标记 |
| 链接文字未译 | `<a>` 标签内的英文文字未翻译 | 链接地址不变，文字翻译 |
| 图片 alt 未译 | `alt="Description"` 保持英文 | 翻译为中文 |

**正反例 — 行内代码遗漏**：

❌ 丢失反引号：
> 使用 class 关键字定义类。

✅ 保留标记：
> 使用 `class` 关键字定义类。

**正反例 — 链接文字**：

❌ 链接文字未译：
```html
<a href="ch03.html#item-42">Understanding Closures</a>
```

✅ 地址不变，文字翻译：
```html
<a href="ch03.html#item-42">理解闭包</a>
```

## 翻译腔陷阱（审阅反馈高频问题）

| 陷阱 | 表现 | 修正 |
|------|------|------|
| 直译连接词 | "这就是为什么..." / "这也是为什么..." | 重写为因果关系："因此..." / "正因如此..." |
| 英文被动直译 | "这被称为..." / "被认为..." | 改为主动或直接陈述 |
| 冗余提示语 | "你会发现..." / "可以看到..." / "请注意..." | 直接陈述事实或结果 |
| 软化词堆叠 | "很容易" / "轻而易举" / "基本上" | 精确描述；技术风险处不能低估复杂度 |
| 口语化插入语 | "正如你..." / "如你所见" | 删除或替换为简洁陈述 |
| 翻译腔副词 | "显然" / "事实上" | 删除；如果不确定是否显然，就别写 |
| 读者称谓不一致 | "你" / "读者" / "我们" 混用 | 全书统一一种称谓 |
| 直译过渡句 | "接下来我们来看看..." | 用判断句或问题开头，不用引导语 |

**正反例 — 直译连接词**：

❌ 直译：
> 这就是为什么 Python 的生成器如此强大——它允许你在不需要将所有数据加载到内存的情况下处理无限序列。

✅ 重写：
> Python 生成器的强大之处在于：它能按需产出数据，处理无限序列时不会耗尽内存。

**正反例 — 冗余提示语**：

❌ 冗余：
> 你会发现，当我们调用 `len()` 时，Python 实际上调用的是 `__len__` 方法。

✅ 直接：
> 调用 `len()` 时，Python 实际调用 `__len__` 方法。
