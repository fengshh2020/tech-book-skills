# 翻译规范

翻译技术书籍时遵循的语言和格式规范。与项目 SPEC.md 互补：本文件是通用规范，项目 SPEC.md 是本书特有规则。

## 翻译原则

1. **信达优先，达意为本**：不追求字面对应，追求读者理解原文的含义
2. **技术术语保留英文**：Python 关键字、标准库名、协议名等一律保留英文
3. **代码绝对不翻**：代码块内容逐字复制，但**代码注释需翻译为中文**（程序输出字符串、异常文本、标识符保留英文）
4. **结构一一对应**：原文几段翻几段，不合并不拆分，保留所有标记

## 术语规则

### 必须保留英文的

- Python 关键字和内建名：`class`, `def`, `return`, `True`, `None`, `import`, `__init__`, `self`
- 标准库模块：`os`, `sys`, `asyncio`, `dataclasses`
- 协议名：`HTTP`, `TCP`, `WebSocket`
- 类型注解：`str`, `int`, `list[str]`, `Optional[int]`
- 命令行命令和选项：`python -m`, `pip install`
- 操作系统概念：`PATH`, `stdin`, `stdout`

### 首次括注英文的

通用中文译法 + 首次括注英文原文：

| 英文 | 中文 |
|------|------|
| decorator | 装饰器 |
| generator | 生成器 |
| iterator | 迭代器 |
| comprehension | 推导式 |
| context manager | 上下文管理器 |
| metaclass | 元类 |
| descriptor | 描述符 |
| coroutine | 协程 |
| event loop | 事件循环 |
| type hint | 类型提示 |
| dunder method | 双下方法 |
| monkey patching | 猴子补丁 |
| duck typing | 鸭子类型 |
| dataclass | 数据类 |
| namespace | 命名空间 |
| scope | 作用域 |
| closure | 闭包 |
| iterable | 可迭代对象 |
| callable | 可调用对象 |

### 不翻译的内容

- 代码块内的变量名、函数名、输出字符串、异常文本（注释需翻译为中文）
- 行内代码 `` `word` `` 中的英文
- 文件名和路径
- 命令行命令
- 人名、公司名、产品名
- 书名（首次括注中文译名即可）
- URL 和邮箱

## 写入规则

### 每个文件写入后立即保存

不要在内存中积累多章内容。一章翻译完成即写入对应文件。

### 文件编码

所有 HTML 文件使用 UTF-8 编码。

### 代码块处理

1. 逐字复制源文件中的代码（变量名、函数名、输出字符串保持英文）
2. **代码注释翻译为中文**（`# This is a comment` → `# 这是注释`），但程序输出和异常文本保留英文
3. `<pre>` 内的 `<em>` 和 `<b>` 替换为 `<strong>`
4. 禁止 `<code>` 嵌套（`<pre>` 内直接写文本）
5. 代码缩进 4 空格
6. 不在 `<pre><code>` 内添加装饰元素；如需代码语言标签或复制按钮，用独立元素放在代码块外，并保持全书统一
7. 代码标题使用 `<p class="CodeListingCaption">` 在代码块下方
8. **代码清单编号必须连续**——如原书有跳跃或插入，重新编为连续序号

## 排版规范

以下规则来自审阅反馈中反复出现的排版问题，必须在翻译时一次做对：

### 标点
1. 禁止中文引号 `""`，使用英文引号或书名号
2. 代码清单标题中的冒号统一使用中文全角冒号 `：`
3. 表题、图题的冒号同样使用全角冒号
4. 引用代码清单时使用紧凑格式，不加多余空格

### 间距
5. 英文与中文之间加空格（`Python 是` 而非 `Python是`）
6. 数字与中文之间加空格（`3 个` 而非 `3个`）
7. 英文括号内全英文内容不加空格（`(Python)`），中英混合时加空格
8. `第 N 章` 中 N 前后加空格（`第 3 章` 而非 `第3章`）

### 标题
9. 破折号使用 `——`（中文双破折号）
10. 目录标题、页面 `<title>`、`<h1>` 三者内容必须一致
11. sidebar 标题使用 `.sidebar-title` 段落，不参与页面标题大纲

### 术语
12. `I/O` 统一使用大写斜杠写法，不在正文中使用 `IO`（类型注解如 `IO[str]` 除外）
13. 技术术语首次出现括注英文，后续统一使用中文译法

## 图片和链接

1. 图片路径统一 `images/xxx`——**必须验证路径指向的图片实际存在**
2. 图片 alt 属性翻译为中文
3. 链接地址不变，链接文字翻译
4. 跨章引用使用 `chapter_file.html#item-N` 格式
5. **交叉引用的章节编号必须正确**——如"参见第 8 章"，确认目标确实在第 8 章

## 校验清单

翻译完成后逐章检查：

### 硬性红线（必须通过）

见 `red-lines.md`。核心项：
- [ ] 每个段落都已翻译，无遗漏（红线：逐段翻译）
- [ ] 代码块除面向读者的注释翻译外与源文件保持一致（变量名、字符串、异常文本、输出不改）
- [ ] 术语首次出现括注英文，全文统一译法（红线：术语规则）
- [ ] 格式完整性（红线：保留 HTML 标签/锚点 ID/链接地址/图片 alt）

### 质量检查（每章自检）
- [ ] 中英文间有空格
- [ ] `第 N 章` 格式统一
- [ ] 代码清单标题用全角冒号
- [ ] 目录标题 / `<title>` / `<h1>` 三者一致
- [ ] sidebar 标题不参与页面大纲
- [ ] 代码清单编号连续无跳跃
- [ ] 交叉引用章节编号正确
- [ ] 无翻译腔直译（参照 `../../shared/translationese-patterns.md`）
- [ ] 代码注释已翻译为中文
- [ ] I/O 统一写法

## 页面设计方向

`style.css` 提供可用的基础样式，不是唯一设计答案。生成页面时应优先保证阅读体验和结构一致性，同时允许根据书籍主题、受众、内容密度和图片素材调整视觉风格。不要为了套用模板牺牲可读性或信息层级。

### 必须保留的体验约束

- 正文宽度、行高、字号和段落间距适合长时间阅读
- 代码块、表格、旁注、术语表在桌面和移动端都清晰可读
- 顶部导航、目录、上一页/下一页、键盘翻页保持可用
- 页面在移动端不横向溢出，打印时隐藏交互控件
- 颜色、对比度和强调样式服务于技术内容，不遮蔽正文

### 建议保留的结构类名

- `.chapter` — 章节主容器
- `.chapter-header` / `.chapter-number` — 章节标题区
- `.chapter-content` — 正文容器
- `.sidebar` / `.sidebar.warning` — 旁注框
- `.CodeListingCaption` — 代码标题
- `.page-nav` / `.prev` / `.next` — 翻页导航
- `.top-nav` / `.toc-toggle` / `.toc-dropdown` — 顶部导航栏
- `.table-wrapper` — 表格滚动容器
- `.glossary-term` — 术语表条目
- `.cover` / `.cover-content` — 封面

视觉主题、布局细节、封面表现、组件装饰和动效都可以调整。优先在 `style.css` 中实现样式；只有单个页面确有特殊语义或资产需求时，才在 HTML 中添加少量局部类名，避免内联样式泛滥。
