# 防懈怠与强制遵从协议

> 供所有书籍 skill 共享。定义防止模型"偷懒""跳过""凭记忆决定"的结构性机制。
> 本协议的核心假设：模型有强烈的"走捷径"倾向，必须用机械化的检查清单和不可跳过的步骤来约束。

---

## 一、问题定义：模型懈怠的 6 种表现

### 表现 1：跳过引用文件

**典型行为**："我记得上次读过这个文件""这个规则我知道"→ 实际上次读取的是另一个文件，或规则细节已更新。

**根因**：模型倾向于复用缓存的"理解"，而非重新读取文件。这在长流程中尤其危险，因为上下文窗口有限，模型可能把"某个文件的印象"和"另一个文件的印象"混淆。

**防护**：
- 每个阶段开始前**必须重新读取**该阶段的引用文件
- 禁止用"我记得"作为跳过读取的理由
- 读取后必须产出"读取确认"记录到 progress.md

### 表现 2：凭目录推断内容

**典型行为**：看到章节标题"第 5 章 异常处理"，就推断内容包含 try/except/finally，而不打开文件验证。

**根因**：目录标题是高度压缩的信息，无法反映实际内容的深度、范围和侧重点。凭标题推断会导致知识点遗漏或错误映射。

**防护**：
- 所有"已阅读"声明必须附带**结构证据**（段落数、代码块数、核心概念列表）
- 禁止仅凭标题推断内容
- 阅读证据协议见 `../shared/progress-protocol.md`

### 表现 3：跳过阶段关卡

**典型行为**：阶段产出看起来"差不多"，就标记为完成，不执行关卡检查。

**根因**：关卡检查是额外工作，模型倾向于认为"我已经做得很好了，不需要检查"。

**防护**：
- 关卡检查是**强制性的**，不是可选的
- 关卡未通过时，必须返回修正，不能标记完成
- 关卡结果必须写入 progress.md，不能只在脑中检查

### 表现 4：伪造阅读证据

**典型行为**：声称"已通读全书"，但提供的证据是泛泛而谈的摘要，无法区分"真正读过"和"凭标题猜测"。

**根因**：模型可以生成看似合理的摘要，但实际上并未读取文件。

**防护**：
- 证据必须包含**不可伪造的信息**：具体段落数、代码块首行内容、特定术语的出现位置
- 连续多章的证据格式不能雷同
- 见 `../shared/progress-protocol.md` 阅读证据协议

### 表现 5：擅自简化整合方式

**典型行为**：把"完全融入并重写"简化为"在主书相关位置插入源书内容"。

**根因**：完全融入需要理解多本书的内容并重新组织，工作量远大于简单插入。模型倾向于选择更简单的方式。

**防护**：
- 在阶段 0 就明确"完全融入"和"缝补式插入"的区别
- 阶段 4 每章完成后检查"读者是否能分辨出内容来源"
- 见 `references/integration-discipline.md` 风格适配规则

### 表现 6：忽视校验结果

**典型行为**：校验发现问题后，不修复就标记完成，或把问题写入"已知限制"而不解决。

**根因**：修复问题需要额外工作，模型倾向于"先完成再说"。

**防护**：
- 覆盖率低于 95% 必须修复，不能只写警告
- 所有失败项必须修复或写入已知限制（附理由）
- 校验结果必须写入 report.md

## 二、强制机制：不可跳过的步骤

### 机制 1：读取确认

每个阶段开始前，必须：

1. **读取该阶段的所有引用文件**（见 SKILL.md 引用文件表）
2. **记录读取确认**到 progress.md：

```markdown
### 阶段 X 启动
- 已读取文件：[列表]
- 读取时间：YYYY-MM-DD HH:MM
- 关键规则摘要：[2-3 条本阶段最关键的规则]
```

3. **不读取就不能开始该阶段**

### 机制 2：证据链

每个产出必须有可追溯的输入证据：

| 产出类型 | 必须附带的证据 |
|----------|--------------|
| 知识点条目 | 源文件段落数 + 核心概念列表 + 提取的行号范围 |
| 整合指令 | 来源知识点 ID + 源书原文摘录 + 目标位置 |
| 新增内容 | 来源标记 + 风格适配说明 + 去重检查结果 |
| 技术断言 | 验证等级（V1-V4）+ 验证方法 |

### 机制 3：自检回环

每个阶段完成后，必须：

1. **执行关卡检查**（见 `references/integration-discipline.md` 阶段关卡）
2. **记录自检结果**到 progress.md
3. **回读验证**：读取刚写入的 progress.md，确认状态正确
4. **全部通过后才能进入下一阶段**

### 机制 4：防跳步检查

以下行为被**严格禁止**，发现时必须立即纠正：

- [ ] 不读取引用文件就开始该阶段
- [ ] 凭标题推断内容而不打开文件
- [ ] 跳过关卡检查就标记阶段完成
- [ ] 用"我记得"代替重新读取
- [ ] 把"缝补式插入"当作"完全融入"
- [ ] 校验发现问题后不修复就继续
- [ ] 连续多章的证据格式雷同
- [ ] 只有"无问题"结论而没有具体证据

---

## 三、责任归属

### 模型责任

- 每个阶段必须按顺序执行，不能跳过
- 每个产出必须有证据支持
- 每个关卡必须通过才能继续

### 用户责任

- 在关键节点（阶段 0 完成、阶段 3 完成）确认方向正确
- 发现模型懈怠时立即指出
- 不催促模型跳过步骤

### 审阅者责任

- review-tech-book 在审阅 generate-book 产出时，重点检查：
  - 整合标记是否覆盖所有计划知识点
  - 风格一致性是否达标
  - 读者是否能分辨出内容来源
  - 来源追溯是否完整
