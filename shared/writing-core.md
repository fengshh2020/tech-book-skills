# Writing Core（写作内核）

generate-book / translate-book / review-tech-book 共用的唯一纪律源。每个 skill 只引用本文件，不重述。

## 铁律

**没有新鲜证据就不产出。不伪造。不缩减。推断必须标注。**

- 产出前真读过源（逐章/逐文件打开读，不凭标题、目录、函数名猜）。
- 论断可追溯：代码库写作每个论断带 `file:line`；审阅每个发现带原文逐字引用 + 行号；调研每条结论带来源。
- 产出深度 ≥ 源深度，不缩水。
- 没验证过的推断标「推断/待验证」，不当结论写；严重指控（技术错误级）必须自己复核实锤（跑代码 / 查源码 / 查官方文档），查不了的标「疑似」。

## 讲解质量（三标准，写书的最高要求）

读者要的是**被讲懂**，不是被展示。逐条对照：

1. **循循善诱**（教学顺序）——从读者已知出发搭台阶，一次只引入一个新概念。新概念出现前，先让读者看到**为什么需要它**：具体问题 / 麻烦先行，概念是答案，不是清单里的下一项。术语和形式化定义在直觉建立**之后**给。
2. **细致入微**（讲解粒度）——知识点讲完整链条：动机 → 机制（为什么有效 / 为什么这样设计）→ 示例 → 边界与陷阱（什么时候不成立）。代码逐段走读：这段做什么、关键行为什么这样写、改动会影响什么——不是"贴代码 + 一句概括"。读者不需要跳出去查资料就能跟上。
3. **娓娓道来**（行文连贯）——用连贯的散文承载推理：段落之间有逻辑接力，前后节环环相扣，像好老师在课堂上自然讲下去。列表和表格只用于真正可枚举的东西（参数表、命令、对比项），不用列表替代讲解。

**检验法**：随机抽一节，想象读者读完合上书——能复述这个知识点"是什么、为什么、什么时候用"吗？代码能说清每一行在干嘛吗？答不上 = 没讲透，回去补讲解，不是补结构。

## 可视化优先（原创内容的媒介选择）

结构、流程、状态转换、架构分层、数据流、对比——**能画就画**：图先承载这些，读者先得全局图景；文字负责图讲不了的（动机、权衡、边界、代码走读）。图不是装饰也不是文字的复述——图说完的事不再用文字说一遍（反冗余红线同样适用于图文之间）。格式标准 **SVG**、作者约定见 `md-authoring.md` 图表节。该图不图（模块协作 / 状态机 / 执行路径用纯文字硬讲）= 讲解不足；图 + 文重复同讲一件事 = 冗余。

## 反冗余（与讲解深度同等重要的红线）

深度不足常被误当成"多写"，于是同一知识点换角度反复讲、结构层层包装——这恰恰毁掉可读性。规则：

- **一个知识点只讲一次**：在对的位置讲透，之后需要时引用（"见 N 章"），不再换措辞、换角度复述。
- **一份代码只走读一次**：同一机制 / 函数的代码不重复贴；再次出现只讲差异。
- **不写不承载知识的栏目**：章前"前置知识清单"、章首"学习目标"、章末"小结 / 要点回顾"、练习题 / 自测题——一律不写。降低认知负荷靠**组织与呈现**：递进排序、一次一个概念、问题先行、例子钉住抽象、复杂流程先图后文、代码即讲解主体；不靠这些栏目（它们是重复内容的藏身处，本身反而增加负担）。
- **区分「参考物」与「复述」**：术语表、速查表、散落各节参数的汇总——读者会**反复回看**的参考物，合法且值得写好；章末小结、要点回顾——把已读内容再说一遍的复述，红线。判据：读者第二三次翻到这页时，它还有没有新信息。
- **结构够用就好**：目录服务认知递进，设计到"每章一个清晰目的、前后依赖顺畅"即停。把预算花在正文讲解深度上，不花在结构包装上——过度精细的结构设计是深度不足的补偿行为。

## 反 AI 腔

产出不得回归均值的通用腔——模板化措辞、空洞大词、无具体观点的"安全"句。治法：写**摘要砍不掉的内容**——具体名词、确切动词、删套话、敢给观点。词汇命中是警告（反复出现才判），**结构命中直接判**：三联排比 / "首先…其次…最后"万能骨架 / 每节"intro→列表→复述" / 复述式结尾（"综上所述…"）/ 段长整齐无节奏变化 / 有正解却"两边都对"的假平衡。词表见 `shared/translationese-patterns.md`（直引 / 学术 / 法律语境豁免）。

## 剪枝

**停止深入 ≠ 停止读取**：继续深入不改变章节计划 / 修复方案时停止深入，但仍需通读确认判断。跳过 / 降级的决定写进 `progress.md`，不只留在对话里。长程状态契约（progress.md 记什么、怎么交接）见 `book-project.md`；子任务开新上下文只回传结果。

## 校验套件（客观兜底，一处定义；各 skill 只引用本表，不重述命令）

CWD = SKILL_DIR。book 形态交付前按序全跑；doc 形态（无 builder 产物）只有模型自检。

| 环节 | 命令 | 检什么 |
|---|---|---|
| 构建 | `python ../shared/scripts/build_html.py {RUN}/src {RUN}/output` | MD → HTML + MD 双格式（手写 SVG 直通、mermaid→SVG、封面/目录 chrome 注入） |
| 产物结构 | `../shared/scripts/validate_output.sh {RUN}/output/` | 资源齐全、完成标记、本地断链、未解析占位符、内容深度 |
| 代码与腔调 | `../shared/scripts/validate_code.sh {RUN}/output/`（修复后可加 `--run-code` 实跑） | 代码块格式与清单编号、术语一致、断链、HTML 结构、翻译腔 + AI 腔计数（动态读 `../shared/translationese-patterns.md`） |
| 多源覆盖 | `scripts/check_coverage.sh {RUN}/knowledge_base/ {RUN}/output/`（仅 generate-book 多源） | 每源深读笔记非空、逐章 `<!-- integrated -->` 标记存在 |

修复模式统一回路：改 `{RUN}/src/*.md` → 重新构建 → 重跑本表。**MD 是源，不手改 HTML。**

## 路径与运行时

- 命令 CWD = `SKILL_DIR`（含 `SKILL.md` 的目录）：`scripts/` 指本 skill 脚本、`../shared/` 指共享资源、跨 skill 写 `../{sister-skill}/scripts/`。skill 内资源相对 `SKILL_DIR`，共享资源在兄弟 `../shared/`（三工具 portable，见仓库根 `install.sh`）。
- 并行子 Agent 是可选优化：仅当 runtime 支持且写入范围不冲突时用，否则串行。
