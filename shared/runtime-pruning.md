# 运行时剪枝规则

> 供长流程书籍 skill 共享。目标是减少不必要的阶段、重复读取和过度分析，让运行过程按任务范围收缩。

## 核心原则

1. **按需读取**：只在当前阶段需要某个参考文件时读取它；不要为了“全面”提前加载所有规范。
2. **跳过条件**：已有可信产物且源输入未变化时，跳过对应阶段，只记录跳过依据。
3. **停止条件**：继续深入分析不会改变章节计划、修复批次、质量判断或读者学习路径时停止深入分析，不为了填满流程继续扫描。**停止深入分析不等于停止读取**——即使判断某个内容不需要深入分析，仍需通读确认判断正确。
4. **范围分层**：先分层，再投入深度。核心路径深读，支撑材料通读后摘要，生成/重复/低风险内容通读确认后登记。分层控制深度，不控制是否读取。
5. **证据优先**：跳过、降级、停止都必须写进 `progress.md` 或报告，不能只保存在对话记忆中。

## 通用跳过条件

- 已有 `progress.md` 标记完成，且产物文件存在、非空、通过对应校验。
- 运行目录已有缓存元数据，且源文件路径、大小或时间戳未变化。
- 用户明确限定章节、文件或问题类型时，不启动全量流程。
- 自动化脚本已完整列出低层问题时，人工报告只写摘要和代表例。
- 前置 skill 的 `report.md` 已提供可信术语表、覆盖表或验证摘要，本轮通读验证影响当前任务的部分。

## 通用停止条件

- 连续扫描只产生同类低优先级问题，且已有批量修复策略。
- 新增发现不改变目标读者判断、学习路径图、章节计划或修复批次。
- 外围文件、章节或资产只提供重复背景，不影响核心解释。
- 当前模式为快速模式，目标问题已验证且未发现阻断风险。
- 代码库分析中，新增 support/reference 文件不会改变架构图、核心路径或章节覆盖表。

## 分层建议

| 层级 | 处理方式 |
|------|----------|
| 核心路径 | 深读、验证、写证据 |
| 支撑路径 | 通读 + 关键行为摘要，不跳过 |
| 低风险重复内容 | 通读确认后摘要，不跳过 |
| 生成/供应商/资产 | 通读确认分类正确后排除，不跳过 |

分层控制分析深度，不控制是否读取。所有文件都应至少被读过一次以确认分类正确。

运行报告必须记录被跳过或降级处理的范围、理由和残余风险。
