# 共享纪律框架 (Shared Discipline Framework)

generate-book 和 review-tech-book 共用的流程纪律。各 skill 的 shared-rules 引用此文件，不再重复定义。

## 铁律

**NO OUTPUT WITHOUT FRESH READ EVIDENCE. NO GATE SKIP. NO TITLE-ONLY INFERENCE. NO CONTENT SHRINKAGE.**

违反这条规则的字面意思，就是违反这条规则的精神。

## 防懈怠机制（模型偷懒的 6 种表现与防护）

模型有强烈的"走捷径"倾向，必须用机械化的检查清单约束。每个阶段开始前对照：

| 表现 | 防护 |
|---|---|
| **跳过引用文件**（"我记得这个规则"） | 每阶段开始前**重新读取**该阶段的引用文件；禁止用"我记得"作为跳过理由；读取后产出"读取确认"记入 progress.md |
| **凭目录/标题推断内容** | 所有"已阅读"声明必须附**结构证据**（段落数、代码块首行、术语位置）；阅读证据协议见 `progress-protocol.md` |
| **跳过阶段关卡** | 关卡检查是强制的；未通过必须返回修正，不能标记完成；结果写入 progress.md |
| **伪造阅读证据** | 证据必须含不可伪造的信息：具体段落数、代码块首行内容、特定术语出现位置；连续多章证据不能雷同 |
| **擅自简化整合/产出** | 阶段 0 就明确"完全融入"与"缝补式插入"的区别；每章完成后检查读者是否能分辨内容来源 |
| **忽视校验结果** | 覆盖率低于 95% 必须修复，不能只写警告；失败项必须修复或写入已知限制（附理由）；校验结果写入 report.md |

**防跳步检查（任一命中 = 立即纠正）**：
- 不读取引用文件就开始该阶段
- 凭标题推断内容而不打开文件
- 跳过关卡检查就标记阶段完成
- 用"我记得"代替重新读取
- 把"缝补式插入"当作"完全融入"
- 校验发现问题后不修复就继续
- 连续多章的证据格式雷同
- 只有"无问题"结论而没有具体证据

## 反合理化表

以下条目适用于所有 skill。各 skill 可追加领域特定条目。

| 如果你这么想…… | 真相是…… |
|---|---|
| "我记得这条规则" | 你不记得。重新读取文件。 |
| "标题已经告诉我足够多了" | 并不够。打开文件完整阅读。 |
| "Gate 大概能通过" | 去运行它。没有"大概"。 |
| "就这一次" | "就这一次"就是这样开始的。 |
| "用户想要速度" | 用户想要质量。 |
| "我已经验证过了" | 重新验证。只接受新鲜证据。 |

## Gate 降级方案

当 workflow.py 不可用时，使用手动验证。降级不等于跳过——必须执行等效检查。

**手动 Gate 检查协议**：
1. 列出该 Gate 的所有检查项（从 skill 流程文件中复制）
2. 逐项检查，在 progress.md 中记录每项结果（通过/失败 + 证据）
3. 所有项通过 = Gate 通过；任何一项失败 = Gate 失败

```markdown
### Gate [N] 手动检查结果 - [日期时间]
- [x] 检查项 1：[具体证据]
- [x] 检查项 2：[具体证据]
- [ ] 检查项 3：[失败原因]
结果：PASS / FAIL
```

## 错误恢复协议

- **可恢复错误**：重试一次，记录失败原因
- **不可恢复错误**：暂停，保存当前状态到 progress.md，询问用户
- **永不静默跳过**：任何错误都必须在 progress.md 中有记录

**阶段中途崩溃恢复**：读 progress.md 定位最后完成阶段 → 验证其输出（存在、非空、大小合理；可疑则从该阶段开头重跑）→ 从下一阶段继续，不从头开始 → 记录恢复点。

**Gate 失败恢复**：记录完整输出到 progress.md → 识别失败项 → 修复（不跳过）→ 重跑 Gate → 连续 3 次失败：暂停问用户。

**子 Agent 失败处理**：

| 失败类型 | 处理方式 |
|---|---|
| Agent 超时 | 记录超时，用更小的任务范围重试一次 |
| Agent 输出为空 | 检查输入是否完整，补充上下文后重试 |
| Agent 输出质量差 | 在 progress.md 记录问题，用更具体的提示词重试 |
| Agent 重复失败（2 次） | 暂停，保存当前状态，向用户报告具体失败原因 |
| Agent 崩溃/异常 | 记录错误信息，跳过该 Agent 的任务，继续其他并行任务 |

## 进度追踪

progress.md 是唯一的进度真相来源。

**初始化**（启动时写入）：
```markdown
# 进度追踪
- Skill：[generate-book / review-tech-book]
- 启动时间：[ISO 8601]
- 输入：[源文件列表 / 代码库路径 / output/ 目录]
- 模式：[单源/多源/代码库 / 仅报告/报告+修复]
- run_dir：[路径]
- workflow.py 可用：[是/否]
```

**每个阶段完成后追加**：
```markdown
## Phase [N] - [名称]
- 完成时间：[ISO 8601]
- 状态：completed / failed / skipped(附理由)
- 输出：[文件路径列表]
- 证据：[结构化证据]
```

运行目录结构、阶段完成协议、阅读证据协议、跨次恢复见 `progress-protocol.md`。

## 责任归属

- **模型**：按序执行不跳过；每个产出有证据；每个关卡通过才继续。
- **用户**：在关键节点（阶段 0、阶段 3 完成）确认方向；发现懈怠立即指出；不催促跳步。
- **review-tech-book**：审阅 generate-book 产出时重点查——整合标记覆盖、风格一致、读者能否分辨来源、来源追溯完整。
