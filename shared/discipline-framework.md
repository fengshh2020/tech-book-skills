# 共享纪律框架 (Shared Discipline Framework)

generate-book 和 review-tech-book 共用的流程纪律。各 skill 的 shared-rules 引用此文件，不再重复定义。

## Gate 降级方案

当 workflow.py 不可用时，使用手动验证。降级不等于跳过——必须执行等效检查。

**手动 Gate 检查协议**：
1. 列出该 Gate 的所有检查项（从 skill 流程文件中复制）
2. 逐项检查，在 progress.md 中记录每项结果（通过/失败 + 证据）
3. 所有项通过 = Gate 通过；任何一项失败 = Gate 失败

```markdown
### Gate [N] 手动检查结果 - [日期时间]
- [x] 检查项 1：[具体证据]
- [x] 检查项 2：[具体证据]
- [ ] 检查项 3：[失败原因]
结果：PASS / FAIL
```

## 错误恢复协议

### 原则
- **可恢复错误**：重试一次，记录失败原因
- **不可恢复错误**：暂停，保存当前状态到 progress.md，询问用户
- **永不静默跳过**：任何错误都必须在 progress.md 中有记录

### 阶段中途崩溃恢复

1. 读取 progress.md，确定最后完成的阶段/子阶段
2. 验证最后阶段的输出（文件存在且非空，大小合理）
3. 如果输出可疑：从该阶段的开头重新执行
4. 从下一个阶段继续，不从头开始
5. 在 progress.md 中记录恢复点

### Gate 失败恢复

1. 记录 Gate 的完整输出到 progress.md
2. 识别失败的具体检查项
3. 修复失败项（不跳过）
4. 重新运行 Gate
5. 连续 3 次 Gate 失败：暂停，向用户报告，请求指导

### 子 Agent 失败处理

| 失败类型 | 处理方式 |
|----------|----------|
| Agent 超时 | 记录超时，用更小的任务范围重试一次 |
| Agent 输出为空 | 检查输入是否完整，补充上下文后重试 |
| Agent 输出质量差 | 在 progress.md 中记录问题，用更具体的提示词重试 |
| Agent 重复失败（2 次） | 暂停，保存当前状态，向用户报告具体失败原因 |
| Agent 崩溃/异常 | 记录错误信息，跳过该 Agent 的任务，继续其他并行任务 |

## 进度追踪

progress.md 是唯一的进度真相来源。

**初始化**（启动时写入）：
```markdown
# 进度追踪
- Skill：[generate-book / review-tech-book]
- 启动时间：[ISO 8601]
- 输入：[源文件列表 / 代码库路径 / output/ 目录]
- 模式：[单源/多源/代码库 / 仅报告/报告+修复]
- run_dir：[路径]
- workflow.py 可用：[是/否]
```

**每个阶段完成后追加**：
```markdown
## Phase [N] - [名称]
- 完成时间：[ISO 8601]
- 状态：completed / failed / skipped(附理由)
- 输出：[文件路径列表]
- 证据：[结构化证据]
```

## 反合理化表（通用条目）

以下条目适用于所有 skill。各 skill 可追加领域特定条目。

| 如果你这么想…… | 真相是…… |
|-----------------|----------|
| "我记得这条规则" | 你不记得。重新读取文件。 |
| "标题已经告诉我足够多了" | 并不够。打开文件完整阅读。 |
| "Gate 大概能通过" | 去运行它。没有"大概"。 |
| "就这一次" | "就这一次"就是这样开始的。 |
| "用户想要速度" | 用户想要质量。 |
| "我已经验证过了" | 重新验证。只接受新鲜证据。 |

## 反偷工减料（通用规则）

遵循 `shared/anti-slacking.md`。通用要点：
- 每个阶段开始时重新阅读参考文件，附带结构证据
- 不跳过子阶段，不凭标题推断
- Gate 没有"大概"

各 skill 追加领域特定要求（如：generate-book 单源要求 1:1 段落映射；review-tech-book 要求每个发现有直接引用）。
