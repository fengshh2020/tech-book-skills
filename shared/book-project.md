# Book Project（书籍项目：工作区与生命周期契约）

generate-book / translate-book / review-tech-book / take-note（book-ingest）共用的**工作区契约**——单一源，各 skill 引用不重述。章节怎么写（格式/组件）见 `md-authoring.md`；写作纪律见 `writing-core.md`；**项目怎么跑**归本文件。

## 工作区布局（`{RUN}` = 项目根）

```
{RUN}/
├── src/               MD 主源：book.yml + NN_*.md（编号 ≥02，00/01 留给封面/目录）
├── progress.md        项目状态——跨 skill、跨窗口（契约见下）
├── knowledge_base/    多源深读笔记 {书名}/*.md（仅 generate-book 多源）
└── output/ + output-md/   builder 产物（HTML / 可移植 MD）——不手改，永远从 src 重建
```

生命周期是产物状态，不是流程关卡：**draft → built → reviewed → fixed → ingested**。任一阶段可恢复：读 `progress.md` → 验证最后产出（存在/非空/无占位符）→ 从断点继续，不从头来。阶段间传递靠**产物 + progress.md**，不靠对话记忆。

## 写作回路（生成端统一，generate-book 与 translate-book 共用）

1. **对齐**（`kickoff.md`）：一轮问清决策 → 复述开跑。
2. **读透**（各 skill 自己的输入纪律）→ 笔记落 `knowledge_base/` 与 `progress.md`。
3. **首章即曳光弹**：第一章写完**立即构建 + 跑校验**，把 HTML 交给用户过目——只需扫一眼深度、口吻、术语、格式对不对，认可即量产（翻译：过目项是术语译法与腔调基线，首章连同术语表初版一起交）。这一步防的是最贵的返工：整本书写完才发现口吻或深度不对。
4. **滚动构建**：构建是分钟级幂等操作，不是终点仪式——首章之后每 3-5 章、或结构变更时，重跑 build + 校验套件（writing-core 表）；漂移在章 N 抓住，不在全书完成后。每章完更新 `progress.md`。
5. **终检**：全书完成后跑全套校验 + 各 skill 底线自检。

## progress.md（跨 skill 项目状态，不是生成端的私有草稿）

- **交接段**（窗口将满 / 中断时主动写）：下一步 + 未决问题 + 已定决策 + 该重读的参考；产物里已有的内容引用路径，不复述。
- **生成端记**：结构决策（含弃用方案）、术语表、逐章进度、自检记录（哪些知识点按检验法验过、哪些没把握）。
- **审阅端起步先读它**：结构意图 + 生产者自标注的薄弱点 = 先验地图，注意力花在刀刃上（不替代审阅者自己的通读）。
- **修复端更新**：逐批修复状态，供中断恢复与用户追查。

## 修复操作（review 报告 → 应用：工作区操作，不是审阅者的模式）

用户说「修复 / 优化 / 按报告修复」时由 review 路由至此：

1. 读最新 `report.md` + `findings.md` → **改源 MD**（`{RUN}/src/*.md`，绝不手改 output/）→ `python ../shared/scripts/build_html.py {RUN}/src {RUN}/output` → 重跑校验套件。
2. 按类别分批，每批后跑校验、失败先修再进：**P0 技术错误**（改前复核原发现属实）→ **P1 讲解与结构**（补讲解链、删冗余主讲与装饰栏目、章节拆合）→ **P2 风格一致性**（腔调、术语、格式）。
3. 不重开完整审阅、不扩张范围；执行中发现的新风险记 `fix-report.md`（批次 / 改动文件 / 验证 / 残余风险），供用户决定是否另开一轮。
4. 遗留产物只有 HTML 无 `src/` → 停下告知：无法干净修复，建议从源重建。doc 形态直接改那份 MD，无需重建。
