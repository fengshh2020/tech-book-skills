# 教学设计参考

审阅教学设计维度时使用的反模式清单和教学理论。阶段 3 维度评审时读取。

---

## 反模式清单

从技术书籍常见错误中提炼，每个反模式都是扣分信号。

### 叙事结构

| 反模式 | 表现 | 修复建议 |
|--------|------|----------|
| 知识堆砌 | 章节是主题列表而非叙事弧线 | 确立痛点→概念→能力→闭环结构 |
| 无动机引入 | "接下来我们学习X"（没有解释为什么） | 先展示痛点/问题，再引入解决方案 |
| 跳跃式教学 | 前后节之间无逻辑衔接 | 添加桥梁内容/过渡段 |
| 孤立示例 | 示例之间无关联，每节一个新场景 | 用递进式示例链，场景演化 |
| 深度一刀切 | 所有主题同等深度 | core 深 supplementary 广 advanced 点到为止 |

### 代码示例

| 反模式 | 表现 | 修复建议 |
|--------|------|----------|
| 玩具代码 | print("hello") 级别的示例 | 展示真实场景的简化版 |
| 缺少错误处理 | 只展示 happy path | 添加错误情况和边界条件 |
| 无上下文片段 | 只有 3 行代码，不知道怎么用 | 展示完整的可运行代码 |
| 版本过期 | 代码在目标版本已废弃 | 更新或标注版本要求 |
| 反模式示范 | 展示了不好做法但没说为什么不好 | 明确标注"不要这样做"及原因 |

### 教学设计

| 反模式 | 表现 | 修复建议 |
|--------|------|----------|
| 定义先行 | 先给形式化定义再解释 | 先用 ELI5 段落建立直觉 |
| 认知过载 | 一次引入 3+ 新概念 | 每段最多引入 1-2 个 |
| 无脚手架 | 要求从零写代码 | 先提供完整示例再逐步要求自主 |
| 无反馈循环 | 读者无法验证理解 | 添加自我检查点或可运行验证代码 |
| 类比滥用 | 类比比概念本身更复杂 | 类比必须比目标概念更简单 |

### 风格一致性

| 反模式 | 表现 | 修复建议 |
|--------|------|----------|
| 语气跳变 | 前文严肃后文口语 | 统一语气基线 |
| 术语不一致 | 同一概念多种叫法 | 建立术语表，严格执行 |
| 深度跳变 | 某章极深某章极浅 | 保持渐进式深度曲线 |
| 格式跳变 | 代码注释语言不统一 | 统一代码注释语言 |

## 教学理论

审阅教学设计判断时参考的认知科学和教学理论。

### 认知负荷理论 (Sweller)

工作记忆有限，教学设计必须管理三种认知负荷——内在（材料难度）、外在（设计不当）、相关（构建心理模型）。设计启示：Worked Examples（先给完整示例，逐步淡出）、Split-Attention（注释嵌入代码）、Subgoal Labeling（代码标注子目标步骤）。

### PRIMM 教学法 (Sentance et al., 2019)

500 名学生验证的五阶段渐进释放——Predict→Run→Investigate→Modify→Make。过早要求从零写代码是编程教育最大的错误之一。

### 类比教学五原则 (Gray & Holyoak, 2021)

1.用学习者理解的源类比 2.多方式强调共享结构 3.解释语义与形式的对应 4.减少外在负荷 5.熟练后再推论。每个类比必须注明"类比在哪里失效"。

### Parsons Problems (Parsons & Haden, 2006)

代码排序完成时间仅为写代码的 50-80%，学习效果无差异，对低自信心学生效果尤佳。对 Python 特别适合（缩进即语法）。

### 自我解释效应 (Chi, 2000)

主动为自己解释的学习者理解更深入。引导性自我解释比自由解释更有效。代码关键步骤旁插入"思考"提示框。

### 双编码理论 (Paivio)

文字+图像同时编码创造更强记忆。"看不见的过程"（调用栈、递归、作用域）都应配图解。

### 间隔重复 (Ebbinghaus)

在遗忘即将发生时复习比集中练习更有效。设计启示：螺旋式课程设计、章末回顾问题、Janki Method 闪卡。

### Feynman Technique / ELI5

如果不能用简单语言解释一个概念，就没有真正理解它。核心概念在技术定义前先用日常语言的"ELI5 段落"解释。

### 建构主义 (Papert)

学习者通过构建有意义的、可分享的人工制品获得最深刻的学习体验。项目应是读者真正想构建的东西。

### CS-SCIC 渐进释放模型

六类教学法（高→低支持）：Copy Code → Targeted Tasks → Shared Coding → Project-based → Inquiry-based → Tinkering。独立项目前先用 Targeted Tasks 做过渡。

### 十大高效教学模式

1. 统一类比系统 2. 先暴露错误再纠正 3. 对比教学法 4. 递进惊喜叙事 5. 极度聚焦 6. 概念性测验>判断性 7. 最少信息先行 8. 两段式问题设计 9. 项目间插 10. 交互式实验场
