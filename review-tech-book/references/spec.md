# 审阅规范

技术书籍审阅的评分框架、输出模板和校验清单。

**教学理论与反模式**：`teaching-reference.md`（4 类反模式 + 10 个理论 + 10 大高效模式）
**工程实践与标杆**：`quality-reference.md`（5 子维度评估框架 + 6 本经典教材方法论 + 在线资源）

## 十六维度评分框架

### 基础质量 (A)

| # | 维度 | 核心问题 | 评估方法 |
|---|------|----------|----------|
| A1 | 技术准确性 | 信息在目标版本下是否正确？ | 代码实机运行、API 签名核对、版本兼容性检查 |
| A2 | 覆盖度 | 核心主题是否全覆盖？ | 对照官方文档主题清单，识别空白区 |
| A3 | 代码质量 | 示例代码是否健壮？ | PEP 8、边界情况、反模式扫描 |
| A4 | 时效性 | 信息是否反映当前最佳实践？ | 废弃 API 检查、PEP 状态确认 |

### 阅读体验 (B)

| # | 维度 | 核心问题 | 评估方法 |
|---|------|----------|----------|
| B1 | 可读性 | 读者能否顺畅阅读？ | 翻译腔、被动语态、长定语、段落节奏 |
| B2 | 讲解深度 | 深度是否匹配目标读者？ | 核心概念深 vs 补充广 vs 进阶点到为止 |
| B3 | 可视化 | 不可见过程是否有图解？ | 双编码原则：调用栈/递归/作用域等是否配图 |
| B4 | 组织节奏 | 信息密度节奏是否合理？ | 高密度→低密度交替、概念→示例节奏 |

### 教学设计 (C)

| # | 维度 | 核心问题 | 评估方法 |
|---|------|----------|----------|
| C1 | 概念引入 | 概念如何首次出现？ | 动机先行 vs 定义先行、ELI5 段落、类比系统 |
| C2 | 类比系统 | 类比是否一致且正确？ | 类比教学五原则、是否说明类比失效处 |
| C3 | 工程实践 | 能否在工作场景使用？ | 工程实践框架（`quality-reference.md`）|

### 能力落地 (D)

| # | 维度 | 核心问题 | 评估方法 |
|---|------|----------|----------|
| D1 | 实践迁移 | 读者能否把书中知识迁移到真实任务？ | 项目化任务、变体场景、场景覆盖 |
| D2 | 反馈闭环 | 读者是否能判断自己理解是否正确？ | 预期输出、检查点、反例说明、错误恢复提示 |
| D3 | 调试能力 | 读者是否学会定位和修复常见错误？ | 错误信息解读、排障流程、失败示例 |
| D4 | 检索能力 | 读者能否快速回查概念、API 和示例？ | 索引质量、术语表、速查表、交叉引用 |
| D5 | 持续学习 | 读者是否知道下一步如何深化？ | 延伸阅读、社区路径、进阶主题边界 |

### 评分标准

每个维度 1-5 分：

| 分值 | 含义 |
|------|------|
| 1 | 严重缺失 — 几乎不存在 |
| 2 | 显著不足 — 有提及但远不够 |
| 3 | 基本达标 — 覆盖核心但不够深入 |
| 4 | 良好 — 有效覆盖，小瑕疵 |
| 5 | 优秀 — 标杆水平 |

### 十六维度与五维度的关系

十六维度是**诊断工具**，识别具体问题。五转化维度是**整合评估**，判断对读者整体效果。

整合方式：
- **读者旅程** ← 综合 C1(概念引入) + B4(组织节奏) + D1(实践迁移)
- **首次成功时间** ← 综合 D2(反馈闭环) + C1(概念引入) + B1(可读性)
- **错误恢复** ← 综合 D3(调试能力) + A1(技术准确性) + C3(工程实践)
- **参考可用性** ← 综合 D4(检索能力) + A2(覆盖度) + A4(时效性)
- **动机有效性** ← 综合 D5(持续学习) + B2(讲解深度) + D1(实践迁移)

五维度评分基于十六维度中相关维度的加权平均 + 质性判断。参考权重：

| 五维度 | 构成维度与权重 | 质性修正规则 |
|--------|---------------|-------------|
| 读者旅程 | C1×0.4 + B4×0.3 + D1×0.3 | C1≤2 时上限为 3 |
| 首次成功 | D2×0.4 + C1×0.3 + B1×0.3 | C1≤2 时上限为 3 |
| 错误恢复 | D3×0.4 + A1×0.3 + C3×0.3 | A1≤2 时上限为 3 |
| 参考可用性 | D4×0.4 + A2×0.3 + A4×0.3 | — |
| 动机有效性 | D5×0.4 + B2×0.3 + D1×0.3 | D1≤2 时上限为 3 |

参考可用性评分必须包含 3-5 个真实检索任务，例如"忘记某个核心概念时能否快速找到定义、示例和版本限制"。记录每个任务的目标、入口、找到答案所需位置和失败原因。

**质性修正规则说明**：当构成维度中有一个极差（≤2），该五维度不可能得到高分，即使其他维度尚可。这防止了机械平均掩盖严重缺陷。

## 输出模板

### 模式化报告范围

| 模式 | 评分范围 | 报告重点 | 省略项 |
|------|----------|----------|--------|
| 深度模式 | 完整十六维度 + 五转化维度 | 新书全面评估、出版级改造、长期质量基线 | 无 |
| 标准模式 | 有证据的风险维度 + 五转化维度 | 目标读者、学习路径、核心技术风险、系统性残留、修复批次 | 无证据的十六维度逐项评分 |
| 快速模式 | 四个层面一句话结论 | 已知问题复查、回归确认、少量高风险点 | 完整评分表、五维度权重计算 |

模式化评分的原则：评分表服务决策，不服务填表。没有证据支撑的维度不强行评分；同类低层问题合并为系统性发现。

## 校验清单

审阅完成前检查：

- [ ] 每个维度都有评分和关键发现
- [ ] 评分有具体证据支撑（不是"感觉"）
- [ ] 技术准确性至少验证了 3 个代码示例
- [ ] 覆盖度对照了官方文档主题清单
- [ ] 问题建议可操作（不是"加强XX"而是"在Ch3第2节添加XX"）
- [ ] 五维度与十六维度的关系逻辑自洽
- [ ] 反模式清单检查了全部 4 类
- [ ] 改进建议按优先级排列
- [ ] **问题归属分类完成**：翻译/整合/审阅三类问题已分开，不在审阅轮次中修复翻译和整合问题
- [ ] **批量处理**：每轮修复至少覆盖一个完整问题类别，未做单点微修补
- [ ] **收敛状态检查**：已评估是否满足收敛标准，如满足则建议结束审阅
