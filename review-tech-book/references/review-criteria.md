# 审阅标准：六类问题的识别信号

找问题时读。尺子在 `../../shared/writing-core.md`（讲解质量三标准 / 反冗余红线）；本文件给每类问题的**具体识别信号与正反例**。

## P0 技术错误

- API 已废弃 / 移除却仍按现行写（跑代码或查 changelog 复核，不凭印象）。
- 示例代码不可运行（能跑就跑：语法错误、错误 import、版本不兼容）。
- 论断与官方文档 / 源码矛盾。
- 图与文字 / 代码矛盾（流程图画了 A→B，代码实际 B→A）。

## P1 讲解不足（对照三标准）

**循循善诱缺失**：
- 新概念无铺垫登场——上一段还在讲 X，下一段突然用 Y 的术语展开。
- 定义先行——开节即形式化定义 / 参数罗列，读者还不知道这东西解决什么问题。
- 认知过载——一段里引入 3+ 个新概念，每个都没讲透就往下走。
- 误解盲区——概念讲得没错，但全书没有一个"读者可能以为…其实…"式对照：没打中读者带来的错误心智模型（对照 generate-book `references/craft.md` 误解驱动）。

**细致入微缺失**：
- 代码贴了不讲——代码块后只有一句"如上所示"，没有逐段走读（做什么 / 为什么 / 改动影响）。
- 讲解链断裂——只有定义 + 示例，缺动机（为什么需要它）或边界（什么时候不成立 / 常见误区）。
- 示例单薄——只有单一典型例，无边界例（何时失效）、无反例（它不是什么），"示例 / 边界"两环形同虚设。
- 关键细节黑箱——"配置超时参数"却不说典型值、调大调小各有什么后果。

**可视化优先缺失**（writing-core）：
- 该图不图——模块协作 / 状态转换 / 执行路径 / 架构分层用纯文字硬讲，读者无法建立全局图景。
- 图退化为装饰——有图但信息量低于文字（流程图只重述段落已说的话）。

**正面样板**（讲透的样子）：动机（处理 10GB 日志时 `list` 会 OOM）→ 机制（生成器为何按需产出）→ 示例（代码逐段走读）→ 边界（只能遍历一次、`zip` 里的陷阱）。

## P1 冗余与装饰结构

- **同一知识点多处主讲**：同一概念 / 机制在两章各自完整讲一遍（交叉引用才是对的）；同一份代码贴两遍各配讲解。
- **换角度复述**：正文讲完后，用表格 / 图 / 列表把同样内容再呈现一遍——除非呈现形式本身新增信息（如散落各节参数的汇总速查）。**图文重复**是它的常见变体：图画完的事紧跟着用文字再说一遍（或反之）。
- **装饰栏目**：章前"前置知识 / 学习目标"、章末"小结 / 要点回顾"、练习题 / 自测题——writing-core 反冗余红线明令不写，出现即 P1（译作除外：源书有的栏目照译不算问题）。
- **结构过度包装**：目录层层嵌套、每章机械同构的三段式小节——结构精致但正文单薄。

## P2 叙事断裂

- 节间无衔接——上节结尾与下节开头没有逻辑接力，像独立文章拼接。
- 知识点堆叠——章节是主题列表，读完记不住哪句是重点、为什么按这个顺序。
- 列表替代讲解——该用散文推理的地方（为什么、怎么回事）用了 bullet 罗列。
- "接下来我们来看 X"式过渡——靠路标词而非内容逻辑连接。

## P2 一致性

- 同一概念多种叫法 / 多种译名（validate_code.sh 的术语检查兜底，人工看漏网的）。
- 语气 / 深度 / 格式跳变（注释语言不统一、代码块语言标注缺失）。
- 清单编号不连续、交叉引用章号错、断链（builder 重建后验证 0 断链）。

## P2 翻译腔 / AI 腔

- 词表命中：对照 `../../shared/translationese-patterns.md`（单次 = 警告，反复 = 判）。
- **结构 tell 直接判**：三联排比 / "首先…其次…最后"骨架 / 每节"intro→列表→复述" / 复述式结尾（"综上所述…"）/ 段长整齐无节奏 / 假平衡（有正解却"两种方式各有优劣"）。
- 密度检验：随机抽 2-3 段做摘要，几乎不丢信息 = 没讲任何具体的东西，AI 腔嫌疑。

## 译作附加检查

- 段落数 源 = 目标（无合并 / 拆分 / 缩减）；代码逐字保留、注释已译。
- 术语首现带英文括注、全书同一译法。
- 源书栏目（含小结 / 练习）照译不增删——译者没有重构权。
