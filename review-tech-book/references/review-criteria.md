# 审阅标准：反模式、教学理论与转化维度

阶段 2-3 评审时读取。审阅十六维度（见 `spec.md`）回答"内容是否正确清晰"；本文件回答"书籍是否真正**转化**读者"，并给识别问题的具体信号。任意技术栈通用。

## 反模式清单（扣分信号）

**叙事结构**：知识堆砌（章节是主题列表非叙事弧）/ 无动机引入（"接下来学习 X"）/ 跳跃式教学（节间无衔接）/ 孤立示例（每节新场景）/ 深度一刀切（所有主题同等深度）。

**代码示例**：玩具代码（`print("hello")` 级）/ 只展示 happy path / 无上下文片段 / 版本过期 / 示范反模式却没说为什么不好。

**教学设计**：定义先行（先形式化定义再解释）/ 认知过载（一段引 3+ 新概念）/ 无脚手架（要求从零写）/ 无反馈循环（读者无法验证理解）/ 类比滥用（类比比概念更复杂）。

**风格一致性**：语气跳变 / 术语不一致（同概念多种叫法）/ 深度跳变 / 格式跳变（注释语言不统一）。**AI 腔（slop）**：回归均值的通用腔——模板化措辞、空洞大词（delve / 值得注意的是 / 赋能 / 综上所述…），本质是**不敢给具体立场**。治法判据：**随机抽一段做摘要，若摘要几乎不丢信息 = 密度不足（slop 嫌疑）**——密度 = 抵抗被摘要的信息增量（见 `shared/writing-core.md` 第六类失败模式）。**词汇命中=警告、结构命中=直接扣分**（更强信号），密度才判、单次词弱；结构 tell 与密度判据的完整清单见 `shared/writing-core.md` 第六类失败模式，词表对照 `shared/translationese-patterns.md` AI 腔节（直引 / 学术 / 法律豁免）。

## 五个转化维度（动态评估，附原文证据）

十六维度是静态验证；以下五维度评估读者读完能做什么、转化是否流畅有动力。每个给评级（优秀/良好/不足/严重缺失）。

**A. 读者旅程**——从翻开到合上的能力成长弧线。查：引言是否声明转化目标（"读完能做 X"而非知识清单）；4-6 个"我能做之前做不到的"里程碑是否交付；是否有死区（连续 30+ 页或 2+ 章能力不增长）；成长曲线是否阶梯上升（提升章与巩固章交替）；前 30%/中 40%/后 30% 是否对应新手/进阶/胜任者的不同需求。

**B. 首次成功时间（TTFS）**——多快能做出满意的事。查：最早能凭已学完成有意义任务的位置；入门书首次成功应在 50-80 页内、进阶书在第 1 章、项目驱动书首个项目在前 2 章；延迟原因（哲学章不让动手 / 环境搭建过长 / 语法速成大章 / 首例不可运行）。

**C. 错误恢复**——代码不工作时（一定会）书是否帮找原因。查：主要概念是否展示常见错误写法并解释为何失败；是否有"看到 X 错误说明你可能忘了 Y"的映射；调试技能是否从早期渐进构建而非推到末章；是否用失败-正面教学法（试有 bug 的代码→观察→修复）。展示错误为何失败（不只说它失败）能显著提升学习效果。

**D. 参考可用性**——读完能否快速回查。查：术语表/索引完整性（主要概念能否查到、首现实质讨论处定义）；章节自包含（跳到第 14 章不需重读 7-13）；代码片段可检索；速查表/对照表；搜索友好。

**E. 动机有效性**——每章是否让读者觉得"值得花 30 分钟"。查：每章声明能**做**什么（"能给任何函数加计时/缓存而不改它"而非"理解装饰器"）；个人相关性（目标读者真想要 vs "第 14 章需要"）；问题先行；动机是否随章节衰减。

**无效动机**（知识清单）："本章介绍 X 机制。"　**有效动机**（能力框架）："想象处理 10GB 日志，`list` 一次性读入会 OOM。学完你能按需处理任意大数据流。"

## 教学理论（判断依据，按需参考）

认知负荷理论（管理内在/外在/相关负荷，Worked Examples 渐进淡出、注释嵌入代码、子目标标注）· PRIMM（Predict→Run→Investigate→Modify→Make，过早要求从零写是编程教育大错）· 类比五原则（源须比目标更简单、须注明失效处）· 自我解释效应（关键步旁插"思考"提示）· 双编码（调用栈/递归/作用域等"看不见的过程"须配图）· 间隔重复（螺旋课程、章末回顾）· Feynman/ELI5（技术定义前先用日常语言）· 建构主义（项目应是读者真想构建的东西）· **近失 / near miss**（展示"几乎对但不对"的对照，反差处大脑才锁死——比正面示例更扎心）· **贡献式结尾**（章末交付新能力/新洞见，不复述总结）· **写给过去的自己**（写你卡住时希望有人给你的那篇）· **具体压倒抽象**（具体例子钉住论点，模糊措辞让作者读者一起自欺）。

## 工程实践（C3 维度，5 子项）

真实场景覆盖 / 代码质量（社区最佳实践、命名、无反模式）/ 工具链整合（调试器/linter/formatter/测试/包管理/CI）/ 调试与排错 / 生产就绪（部署/安全/日志监控/配置）。每项 1=缺失 … 5=可直接应用。

**优秀标杆**（判断"优秀实践"参照的特质）：抽象层次可迁移、设计配方清晰、项目驱动、即时回报、叙事与代码交织、调试优先的科学家思维。**权威资源**：以目标语言/框架的官方文档为最终权威（Python 例：docs.python.org、PEP 索引）；换技术栈时替换为该栈的 canonical 文档与标杆教材。
