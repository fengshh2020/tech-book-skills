## 铁律 (IRON LAW)

**NO FINDING WITHOUT DIRECT QUOTE. NO GATE SKIP. NO SKIM-ONLY REVIEW. NO SHALLOW SCORING.**

没有直接引用就没有发现。不跳过关卡。不只扫不读。不浅层打分。

违反此规则的字面含义，就是违反此规则的精神。

## 预检清单

启动前验证以下条件。任何一项失败 = 停止并告知用户。

```bash
# 1. 确认 output 目录存在（审阅的输入）
test -d output/ || echo "FAIL: output/ directory not found — nothing to review"

# 2. 确认 HTML 文件存在
compgen -G "output/*.html" >/dev/null || echo "FAIL: no HTML files in output/"

# 3. 确认至少有 3 个内容页（排除 cover/toc）
count=$(ls output/*.html 2>/dev/null | wc -l)
[ "$count" -ge 3 ] || echo "WARN: only $count HTML files — may be too few for meaningful review"

# 4. 确认 scripts 可用
test -f scripts/validate_code.sh || echo "WARNING: validate_code.sh not found, code validation will be manual"
```

**预检失败处理**：
- output/ 不存在 → 告知用户"没有可审阅的内容"，请求先用 generate-book 生成书籍
- HTML 文件为空 → 同上
- 脚本缺失 → 记录警告，改用手动验证（见 `shared/discipline-framework.md`「Gate 降级方案」）

## 标准关卡自检清单

Gate 编号：Gate 1=扫描，Gate 2=精读，Gate 3=打分，Gate 4=报告，Gate Fix=修复。

每个关卡运行前，确认以下均不为真：
- 任何参考文件在本阶段未被重新读取
- 任何"我已读取"的声明缺少结构证据
- 任何发现缺少来自原文的直接引用
- 关卡检查未实际运行（仅声称已运行）

如有任何一项为真：先修复再运行关卡。

## 反合理化表

通用条目见 `shared/discipline-framework.md`「反合理化表」。审阅特定补充：

| 如果你这么想…… | 事实是…… |
|----------------|----------|
| "标题已经告诉够了" | 不够。打开章节逐字读。 |
| "我凭记忆打分就行" | 凭证据打分。记忆不是证据。 |
| "报告里再补问题" | 现在就记录发现。报告只汇总，不创造。 |

## 反偷工减料规则

通用规则见 `shared/discipline-framework.md`「反偷工减料」。审阅特定要求：
- 每个发现必须有直接引用（原文 + 行号 + 证据等级）
- 不跳过章节——所有章节必须至少略读
- 🔴/🟠 问题必须达到 V2+ 证据等级

## 证据等级体系

审阅发现的证据强度分为 4 级。严重程度必须与证据等级匹配。

| 等级 | 名称 | 定义 | 适用场景 |
|------|------|------|----------|
| V1 | 声明验证 | 可通过文档/API 规范验证 | API 声明、版本特性、语法正确性 |
| V2 | 代码验证 | 代码实际运行验证 | 代码示例、可运行性、输出正确性 |
| V3 | 交叉验证 | 多源交叉验证 | 事实性声明、最佳实践、行业标准 |
| V4 | 深度验证 | 深入分析+上下文验证 | 架构决策、设计模式、教学方法论 |

**严重程度与证据等级的对应关系**：
- 🔴 严重问题：至少 V2（代码验证）
- 🟠 中等问题：至少 V2
- 🟡 轻微问题：V1 可接受
- API/版本声明：V1 或 V3

## 发现质量控制

### 发现格式（严格遵循）

```
### [N]. [章节] [标题] [🔴/🟠/🟡]
- **位置 (Location)**：`ChX line NNN-NNN`
- **原文 (Quote)**：[原文直接引用——逐字复制，不可改写]
- **问题 (Issue)**：[具体分析——为什么这是问题，不是泛泛描述]
- **证据 (Evidence)**：[V1/V2/V3/V4 + 验证方法]
- **影响 (Impact)**：[对读者的具体影响——理解障碍、学习中断、实践错误等]
- **修复 (Fix)**：[具体修复方法——可操作的步骤，不是泛泛建议]
```

### 发现有效性检查

**无效发现**（不要写入报告）：
- 没有直接引用的发现
- 只有泛泛描述（"这个章节不太好"）而无具体问题
- 🔴/🟠 问题但证据等级仅为 V1
- 修复建议不可操作（"改进一下"）

**有效发现**（应该写入报告）：
- 有原文逐字引用 + 行号
- 问题分析具体到段落/句子/代码行
- 证据等级匹配严重程度
- 修复建议可操作（具体改什么、怎么改）

### 批量检查（每 5 章）

- 跨章节术语一致性
- 发现严重程度分布是否合理（不应全部🔴或全部🟡）
- 证据等级分布是否合理（不应全部 V1）
- 是否存在重复发现（同一问题在不同章节重复报告）

## 失败模式识别

**1. 跳过重新读取**
- 模型说："我之前已经加载过 spec 了"
- 真相：上下文被压缩，具体评分标准已遗忘
- 检测：progress.md 中缺少本阶段的读取确认
- 修复：重新读取参考文件，记录确认并附结构证据

**2. 仅略读（标题推断变体）**
- 模型说："我审阅了所有章节"，但发现项使用泛泛描述
- 真相：章节只扫描了结构，内容并未真正阅读
- 检测：发现项缺少直接引用；🔴/🟠 问题的证据等级仅为 V1
- 修复：重新阅读标记章节，添加带行号引用的直接引用

**3. 关卡绕过**
- 模型说："关卡通过——所有章节已审阅"
- 真相：章节只是被列出，并未真正阅读；发现项是捏造的摘要
- 检测：findings/phase2.md 中无章节证据；深读章节无直接引用
- 修复：重新阅读章节，记录段落数 + 术语 + 直接引用

**4. 浅层打分**
- 模型说："所有维度已打分"
- 真相：分数是粗略估算，无证据支撑；或所有维度都打 7/10
- 检测：评分无直接引用支撑；各维度分数均匀一致
- 修复：用具体证据重新打分：直接引用 + 问题 + 影响

**5. 发现注水**
- 模型说："我找到了 20 个问题"
- 真相：一半以上是微小格式问题或重复发现
- 检测：🔴 问题占比 < 10%，或多个发现指向同一根因
- 修复：合并同类发现，聚焦系统性问题

## 质量标准

- 结论基于证据，而非直觉
- 聚焦系统性问题，而非零散罗列
- 每个发现有直接引用（原文 + 行号 + 证据等级）
- 评分有具体证据支撑，不允许均匀评分
- 严重程度与证据等级匹配
- 修复模式：每个批次后验证 HTML、导航、编号、代码
- 输出可通过 report.md 进入 generate-book 修复流程
