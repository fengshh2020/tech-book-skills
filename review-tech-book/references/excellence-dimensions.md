## 为什么需要这些维度

当前 skill 的十六维度覆盖了"内容正确、结构清晰、教学设计合理"——这是**静态验证**。但专业出版编辑还关注**动态转化**：读者读完这本书后，到底能做什么？这个转化过程是否流畅、有动力、能独立持续？

以下五个转化维度来自专业出版实践（O'Reilly、Manning、Pragmatic Bookshelf、No Starch Press 的审稿标准）、认知科学研究（Dreyfus 技能获取模型、Diátaxis 文档框架、IBM 技术信息质量框架），以及大规模读者数据（Brown Rust Book 交互版实验）。

## 维度 A：读者旅程（Reader Journey）

**核心问题**：读者从翻开这本书到合上它，经历了怎样的能力成长弧线？

**为什么重要**：一本书可以每章内容正确、逻辑连贯，但仍然无法让读者感受到"我在进步"。没有成长弧线的书，读者会在 200 页后放弃，无论后续内容多好。

### 检查项

1. **转化声明**：书的引言/前言是否明确声明了读者的转化目标？（如"读完本书，你将能从 Python 新手成长为能写生产级代码的开发者"。如果只说"你将学习 X、Y、Z"，那是知识清单，不是转化声明）
2. **里程碑映射**：识别 4-6 个读者应该感受到"我能做到之前做不到的事"的关键节点。检查这些节点处的内容是否确实交付了对应的能力
3. **死区检测**：是否存在连续 30+ 页（或 2+ 章）读者感知能力不增长的段落？这些是"死区"，读者会在此处失去动力
4. **成长曲线形状**：理想曲线是阶梯式上升（快速提升 → 短暂巩固 → 再次提升），不是线性平坦。检查书中是否有"巩固章节"（主要复习和延伸前一阶段概念）穿插在"提升章节"之间
5. **Dreyfus 模型适配**：书中前 30% 是否面向新手（需要明确规则、完整示例、手把手指导）？中间 40% 是否面向进阶者（需要原理解释、部分自主）？后 30% 是否面向胜任者（需要架构决策、整合挑战）？

### 好的读者旅程示例

> Ch1-2：环境搭建 + 第一个程序运行（能力基线：我能让 Python 工作）
> Ch3-5：核心语法 + 变量函数（能力跳升：我能写有用的脚本）
> Ch6-7：函数进阶 + 类（能力跳升：我能组织复杂逻辑）
> Ch8-10：异常 + 集合 + 生成器（巩固+延伸：我的代码更健壮了）
> Ch11-14：IO + 继承 + 元类（能力跳升：我能处理真实场景）
> Ch15-18：类型 + 异步 + 打包（能力跳升：我能写生产级项目）

### 差的读者旅程示例

> Ch1：哲学（无能力交付）
> Ch2：环境搭建 + t-string（能力交付被打断——代码不可运行）
> Ch3：语法速成 1800 行 15+ 新概念（认知过载，能力不增长反而下降）
> Ch4：项目结构（学习目标错配，读者预期落空）

## 维度 B：首次成功时间（Time to First Success, TTFS）

**核心问题**：读者打开这本书后，多快能做出一件让自己满意的事？

**为什么重要**：TTFS 是维持动机的关键指标。Head First 设计哲学的核心就是"让读者尽快感受到成就感"。Pragmatic Bookshelf 的审稿模板直接问："读者读完这本书后能做什么之前做不到的事？"——隐含期望是这个转化从第 1 章就开始。

### 检查项

1. **首次成功定位**：识别书中最早的位置，读者仅凭已学内容就能完成一个有意义且令人满意的任务
2. **TTFS 测量**：从书的开头算起，首次成功出现在第几页/第几章？
3. **基准对比**：
   - 入门书：首次成功应在 50-80 页内（约第 1-2 章）
   - 进阶书：首次成功应在第 1 章内
   - 项目驱动书：首个项目应在前 2 章
4. **障碍分析**：如果 TTFS 过长，分析延迟原因——是否需要太多前置安装/配置？是否有错误示例打断？是否有认知过载章节？

### 首次成功延迟的典型原因

- 第 1 章讲哲学/动机但不让读者动手
- 第 2 章的环境搭建步骤过长
- 第 3 章是"语法速成"大章，15+ 新概念但无实践出口
- 首个代码示例不可运行
- 首个项目需要安装 5+ 依赖、配置构建系统

## 维度 C：错误恢复与故障排除（Error Recovery）

**核心问题**：当读者的代码不工作时（一定会不工作），这本书帮他们找出原因了吗？

**为什么重要**：大多数技术书只展示"快乐路径"——如果一切顺利，做这些。但真实读者会遇到版本不匹配、平台差异、拼写错误、概念误解。Brown Rust Book 研究证实：针对常见误解的教学干预（展示为什么代码失败，而不只是它失败了）提升了测验成绩 +20%。

### 检查项

1. **预期错误展示**：对每个主要概念，书中是否展示了最常见的错误写法并解释为什么失败？
2. **错误-概念映射**：是否有"如果你看到 `NameError: name 'x' is not defined`，你可能忘了……"类指导？
3. **调试技能渐进**：调试技能是早期就开始逐步构建，还是被推到最后一章？
4. **故障排除旁注**：是否有系统性的"陷阱警告"/"如果遇到 X，试试 Y"类旁注？
5. **失败-正面教学法**：书中是否使用"试试这段有 bug 的代码，观察会发生什么，然后修复它"作为教学模式？

### 错误恢复评级

| 级别 | 表现 |
|------|------|
| **优秀** | 每个主要概念都有常见错误展示、错误-概念映射、调试旁注，调试技能从早期开始渐进构建 |
| **良好** | 有故障排除旁注但不系统，调试集中在单章 |
| **不足** | 只展示快乐路径，偶有"注意"提示但不帮助诊断 |
| **严重缺失** | 全书无错误恢复指导，读者卡住时无自解路径 |

## 维度 D：参考可用性（Reference Usability）

**核心问题**：读者读完这本书后，能否快速找到以前学过的特定信息？

**为什么重要**：技术书有两个用途——首次学习（顺序阅读）和后续查找（非顺序检索）。大多数读者花更多总时间在后者。Diátaxis 框架明确区分了 Tutorial（学习）和 Reference（查阅）两种需求——优秀的书同时服务两者。

### 检查项

1. **术语表/索引完整性**：每个主要概念能否通过术语表或索引找到？术语是否在首次实质性讨论处定义？
2. **自包含章节**：读者能否跳到第 14 章而不需要重读第 7-13 章？前置概念是否有明确回溯引用？
3. **代码片段可检索性**：能否找到特定任务的示例（如"如何写自定义描述符"）而不需要通读整章？
4. **速查表/对照表**：是否有总结表、速查框、"方法→能力"映射表等检索辅助？
5. **搜索友好性**（数字格式）：标题和术语是否为全文搜索优化？

### 回溯引用质量评级

| 级别 | 表现 |
|------|------|
| **优秀** | 每章开头有前置概念清单（"本章需要你理解 X（第 6 章）和 Y（第 8 章）"），术语表全覆盖，有速查表 |
| **良好** | 术语表较全但部分遗漏，偶有回溯引用但不系统 |
| **不足** | 术语表不完整，章节间无回溯引用，读者必须自行记忆前置内容 |
| **严重缺失** | 无术语表或术语表严重不完整，无索引，数字格式无搜索优化 |

## 维度 E：动机有效性（Motivational Effectiveness）

**核心问题**：每个章节是否让读者感到"我值得花 30 分钟学这个"？

**为什么重要**：读者放弃技术书的第一原因不是内容错误或不清楚，而是**失去目的感**。spec.md 的系统性问题清单 #3 已标记"动机说明递减"，但只检查动机是否"存在"，不检查是否"有效"。

### 检查项

1. **能力框架**：每章是否声明读者学完后能**做什么**（不只是知道什么）？"你将理解装饰器"不是好框架。"你将能给任何函数添加计时、缓存、权限控制而不修改它"是好框架
2. **个人相关性**：这个能力是否是目标读者真正想要的？还是抽象/工具性的（"第 14 章需要这个"）
3. **问题先行**：是否先展示令人头痛的问题再给出解决方案？还是直接跳入机制讲解
4. **动机衰减曲线**：统计每章开头动机段的质量。前几章动机是否比中后章节强？衰减是否严重

### 动机质量对比

**无效动机**（知识清单式）：
> "本章将介绍 Python 的生成器和协程机制。"

**有效动机**（能力框架式）：
> "想象你在处理一个 10GB 的日志文件。如果用 `list` 一次性读入，你的程序会直接内存溢出。学完本章后，你将能按需逐行处理任意大小的数据流——无论是文件、网络响应还是实时传感器数据。"

## 使用方式

在 SKILL.md 的阶段 3 中，审阅者应对照本文件的五个转化维度逐项检查。每个维度给出评级（优秀/良好/不足/严重缺失）并附原文证据。

这些维度**不替代**十六维度——它们**补充**十六维度，从"读者转化"角度评估同一本书。五转化维度的评分基于十六维度中相关维度的加权平均 + 质性判断，权重和修正规则见 `spec.md`。最终评分应同时反映十六维度（内容质量）和五转化维度（转化效果）的评估结果。
