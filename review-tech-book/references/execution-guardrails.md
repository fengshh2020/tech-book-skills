# 审阅执行护栏

> 供 review-tech-book 使用。目标是提高审阅效率，并降低大模型在长流程中跑偏、过度发现、重复报告和不按模式执行的概率。

## 1. 模式锁定

开始审阅前必须写入本轮模式：深度 / 标准 / 快速。模式一旦写入 `progress.md`，除非用户明确改变范围，不得自动升级。

| 模式 | 允许做什么 | 禁止做什么 |
|------|------------|------------|
| 快速 | 验证指定问题、读取相关章节、给层面级结论 | 扩展为全书评分、补扫无关章节 |
| 标准 | 评估有证据的风险维度、五转化维度、修复批次 | 为填满十六维度而搜索低风险材料 |
| 深度 | 全量评分、出版级问题归因、完整路径分析 | 忽略跳过条件或重复粘贴自动化日志 |

## 2. 证据预算

证据预算限制精读阶段（阶段 2b）的深度验证数量，防止无限扩散。**不适用于阶段 2a 的通读**——通读覆盖全部章节，没有预算限制。

| 模式 | 通读覆盖 | 精读章节（2b） | 代码/API 验证 |
|------|----------|---------------|---------------|
| 快速 | 全部章节通读 | 通读红旗章节 + 用户指定章节 | 验证目标断言 |
| 标准 | 全部章节通读 | 通读红旗章节 + 强制覆盖章节 | 逐个验证关键断言 |
| 深度 | 全部章节通读 | 通读红旗章节 + 强制覆盖章节 + 补充章节 | 逐个验证关键断言 |

超过精读预算前必须说明新增精读会改变哪个判断：目标读者、学习路径、严重程度或修复批次。不能改变判断则停止精读扩展。

## 3. 发现上限

报告不是问题仓库。每轮报告只保留能推动决策的发现：

- 核心问题 Top3 必须来自已验证发现。
- 同类低层问题合并为一个系统性发现。
- 标准模式每个归属类别最多列 5 个问题。
- 快速模式只列目标问题和直接相关风险。
- 低优先级问题只进入“后续观察”，不展开长篇证据。

## 4. 停止哨兵

停止哨兵只适用于精读阶段的深度扩展，**不适用于通读阶段**。通读必须覆盖全部章节，不允许提前停止。

出现任一情况时停止精读扩展，转入报告或询问用户：

- 新发现连续属于同一低优先级类别，且已有修复批次。
- 新证据不改变评分、严重程度、学习路径图或修复批次。
- 自动化脚本已覆盖该类问题，人工继续扫描只会增加重复样本。

**绝对不允许停止的情况：**
- 通读阶段尚未覆盖全部章节时。
- 还有章节未提供阅读证据（结构数据 + 内容摘要 + 术语列表）时。
- 模型"觉得"剩余章节不太可能有问题时——这不是证据。

## 5. 遵从清单

每阶段结束前检查：

- [ ] 模式是否仍与用户请求一致？
- [ ] 是否超出证据预算？若超出，是否记录理由？
- [ ] 是否把自动化日志复制成报告主体？
- [ ] 是否把生成阶段应修的问题当成审阅阶段逐点任务？
- [ ] 是否存在未经 V1-V3 支撑的严重结论？
- [ ] 是否按修复批次组织建议，而不是按发现顺序散列？

任何一项不通过，先修正当前阶段产物，再进入下一阶段。
