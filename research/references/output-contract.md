# Finding Block 规范

research 产出的标准格式。既是独立 MD 文件，也可内联嵌入父 skill 上下文。

## 结构

```markdown
## Answer
{1-3 句直接回答原问题。不读全文也能拿走。}

## Evidence
- {论断} — [V{1-4} {类型}] — {来源：URL / 文件:行号 / 文档章节}
- {论断} — [V{1-4} {类型}] — {来源}

## Gaps
- {未解问题} — {为什么没找到：源不存在 / 访问受限 / 需要实机验证}
- {未解问题} — {需要什么额外信息}

## Meta
- 来源数：{N}
- 置信度：{high / medium / low}
- 升级：{no / yes} — {理由}
```

## 字段说明

### Answer
- 1-3 句，直接回答
- 不加"根据调研"等前缀
- 有明确答案就给，没有就说"未找到确定性答案"

### Evidence
- 每条一行：论断 + 证据等级 + 来源
- 证据等级按 writing-core V1-V4
- 来源必须具体：URL / `file:line` / 文档章节号
- 🔴🟠 级论断须 ≥V2

### Gaps
- 诚实列出未解问题
- 说明为什么没找到（不是"还需要更多研究"这种空话）
- Gaps 非空不等于调研失败——部分答案仍有价值

### Meta
- **来源数**：查了多少个独立来源
- **置信度**：
  - `high`：≥3 个独立来源交叉验证，无矛盾
  - `medium`：1-2 个来源，或来源间有小矛盾
  - `low`：仅 1 个来源，或来源可信度不高
- **升级**：
  - `no`：答案足够完整
  - `yes`：3 轮迭代耗尽仍有 Gaps，调用方应考虑升级

## 可组合性协议

Finding Block 可被其他 skill 内联消费：

1. **tech-proposal**：定向调研请求 → Finding Block → 检查 Gaps/证据等级/假设推翻
2. **generate-book**：验证论断、查文档、对比选型 → Finding Block 嵌入章节
3. **review-tech-book**：验证书中的技术论断 → Finding Block 作为审阅证据

消费方检查清单：
- Gaps 非空 → 标为待定或追加调研
- 证据等级不够 → 降级或标 `[!caution]`
- 发现推翻假设 → 回到上游重新评估
