# 子 Agent 编排协议（Sub-Agent Orchestration Protocol）

> 适用于 generate-book 所有阶段。核心问题：LLM Agent 并行能力有限（通常 3-5 个），基于 Web 的源书存在链接/引用顺序依赖，无约束执行会导致资源争用和上下文丢失。
> 通用错误恢复、子 Agent 失败处理、进度追踪见 `shared/discipline-framework.md`；本文件只定义**编排策略**与 agent-spawning 规格。

## 全局约束

| 约束 | 值 | 理由 |
|---|---|---|
| 最大并发 Agent 数 | **5** | 平衡速度与资源 |
| 单 Agent 超时 | 10 分钟 | 防止 Agent 挂起 |
| 失败重试次数 | **1** | 同样方式失败两次 = 方法有误 |
| 单 Agent 上下文限制 | ~50k tokens | 过多上下文导致质量下降 |

## Phase 0：深度阅读

**编排**：每本书一个 Agent，书内章节严格顺序。最多 3 本书并行。

| 子阶段 | Agent 模式 | 说明 |
|---|---|---|
| 0.1 | 单 Agent | 清点所有源书（标题/章节数/格式），输出 `inventory.md` |
| 0.2 | 每书一 Agent，最多 3 并行 | 逐章深度阅读（书内串行），每章写阅读证据 + 草稿索引条目 |
| 0.3 | 每书一 Agent，最多 3 并行 | 整合为该书最终 `index.md`（可与 0.2 对不同书重叠：A 书读完即起 A 索引 Agent，B/C 仍在读） |
| 0.4 | 单 Agent | 覆盖度对比（须所有索引完成） |
| 0.5 | 单 Agent | Gate 检查 |

**同一本书内章节不能并行**：章节间有认知递进；索引须记录跨章主题映射；风格基线需端到端一致性分析。

**基于 Web 的源书**：进下一章前解析当前章所有引用——指向外部站点则记 URL 不跟踪；指向本书他章则标为交叉引用并继续当前章。

**Task 模板骨架（0.2 阅读Agent）**：角色=书阅读agent；约束=按序读不跳章/每章实读不凭标题/章内引用章内解决/每章记阅读证据(段落数+代码块数+术语)/按 multi-read-architect.md 格式输出/>=1000行/10分钟超时；输入=书路径+multi-read-architect.md；输出=`.book-doc/knowledge_base/{book}/index.md`。

## Phase 1：架构设计

**编排**：以单 Agent 顺序为主，仅章节计划起草可有限并行。

| 子阶段 | Agent 模式 | 说明 |
|---|---|---|
| 1.1 | 单 Agent | 加载所有索引 + 覆盖度对比，构建源材料内存表示 |
| 1.2 | 单 Agent | 跨书分析（需全局视图，无法分片） |
| 1.3 | 单 Agent | 目录设计（须整体连贯，并行会不一致） |
| 1.4 | 最多 3 并行 | 章节计划起草——每 Agent 接收 TOC + 分析（只读），产出负责章的计划，不改 TOC/分析 |
| 1.5 | 单 Agent | 反向覆盖——验证每源每个主题都映射到章节/小节，识别孤立主题 |
| 1.6 | 单 Agent | Gate 检查 |

**大部分不能并行**：架构需全局视角，跨书分析无法分片；目录需整体连贯；章节计划须感知前后章以设计过渡。

**索引过长**（单 Agent 装不下）：先读所有索引的"整合就绪摘要"+"教学理念"，再分批读逐主题分析；最终须输出一对统一文件（`source-architecture.md` + `plan.md`）。

**Task 模板骨架（1.4 计划Agent）**：输入自包含=目标TOC+跨书分析+相关索引摘录；约束=不改TOC/分析、每章计划含源映射+方法论选择+合成方式、标注与相邻章过渡、10分钟超时；输出=负责章的整合计划。

## Phase 2：章节生成

**编排**：严格每次一章（章间串行）；章内小节在无顺序依赖时可并行（最多 3）。

| 子阶段 | Agent 模式 | 说明 |
|---|---|---|
| 2.1 | 每章单 Agent | 加载该章计划 + 相关索引摘录 + 风格基线 |
| 2.2 | 最多 3 小节 Agent 并行 | 小节生成——无顺序依赖时并行，有递进依赖则串行 |
| 2.3 | 单 Agent | 质量门控——合并小节为完整章节，跑 G1-G8（通过→继续/失败→重写） |
| 2.4 | 单 Agent | 进度记录（门控通过后） |
| 2.5 | 单 Agent | 批量检查（每 5 章） |

**章节不能并行**：章节间有叙事连贯，后续章引用前面输出；质量问题会传播（第 1 章错则 2-5 章引用全错）；逐章门控避免累积返工。

**小节可并行条件**：无顺序依赖、每小节 Agent 收到完整整合指令+风格基线、合并时检查过渡。
**不可并行条件**：小节间有递进（1.1 是 1.2 前置）、须维护统一叙事弧。

**Task 模板骨架（2.2 小节Agent）**：输入自包含=小节整合指令+相关索引摘录+风格基线(主书1-2段)+术语约定+前节摘要(2-3句续连贯)；约束=整合级 L3/L4(禁直接插入)、所有内容加`<!-- integrated -->`标记、新代码加 V1-V3 标签、匹配风格基线、MD 格式(md-authoring.md)、10分钟超时；输出=小节 MD + 标记列表。

## Phase 3：验证

**编排**：可并行（最多 3），任务相互独立。

| 子阶段 | Agent 模式 | 说明 |
|---|---|---|
| 3.1 | 单 Agent | 覆盖度验证（plan.md 所有 ID 有标记 + 源书反向覆盖） |
| 3.2 | 单 Agent | 技术验证（跑代码块、验 API、版本兼容） |
| 3.3 | 单 Agent | 一致性验证（术语/风格/交叉引用） |
| 3.4 | 单 Agent | 汇总统一报告 + 通过/失败判定（须 3.1-3.3 全完成） |

## 错误恢复（agent 特定，通用见 discipline-framework.md）

通用 Agent 失败处理（超时/输出空/质量差/重复失败/崩溃）见 `shared/discipline-framework.md`「错误恢复协议」。agent 编排特定补充：

| 错误类型 | 恢复策略 |
|---|---|
| Agent 上下文溢出（输出截断） | 将任务拆分为更小子任务 |
| 依赖冲突（前置输出与预期不符） | 检查前置输出；必要时回滚到依赖阶段 |
| 网页读取失败（404/超时/反爬） | 重试一次；仍失败则标"源不可用"记 progress.md |

**不允许**：静默跳过失败 Agent / 用占位符替代失败内容 / 降质量标准适应 Agent 能力限制。

## 进度跟踪

每个 Agent 启动/完成/失败记入 `progress.md`（通用进度协议见 `shared/discipline-framework.md`「进度追踪」+ `shared/progress-protocol.md`）：

```markdown
### Agent Tracking
| Agent ID | Phase | Sub-Phase | Task | Status | Output |
| P0-0.2-A | 0 | 0.2 | Book A reading | done | draft entries |
| P0-0.2-C | 0 | 0.2 | Book C reading | fail->done | draft entries |
```

## 并发调优建议

| 场景 | 建议并发数 | 理由 |
|---|---|---|
| <= 3 本源书 | 3 | 每书一 Agent；Phase 0 一批完成 |
| 4-6 本源书 | 3-4 | Phase 0 分两批；避免资源争用 |
| >= 7 本源书 | 3 | 严格分批，每批 3 本，确保单 Agent 质量 |
| 章节生成（短章节） | 1（章间）+ 3（章内） | 短章节允许 3 路小节并行 |
| 章节生成（长章节） | 1（章间）+ 1（章内） | 长章节内容多；单 Agent 确保连贯 |
| 验证 | 3 | 任务相互独立；完全并行安全 |
