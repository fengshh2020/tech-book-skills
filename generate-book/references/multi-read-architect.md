# 多源：深度阅读与架构设计（Phase 0-1）

> 供 generate-book 多源模式使用。Phase 0 为每本源书生成深度知识索引；Phase 1 基于索引设计整合架构。
> **核心原则**：架构设计建立在深入理解之上——不理解材料就无法绘制蓝图。架构是分析工作，不是目录拼接。

## Phase 0：深度知识索引

每本源书生成一份 >= 1000 行的知识索引，存于 `.book-doc/knowledge_base/{source-book-name}/index.md`。

**为什么需要这种深度**：摘要式提取（每章 5-15 条目、200 字）有三个致命缺陷——(1) 信息丢失（压缩掉方法论差异）、(2) 上下文断裂（不记录章节间认知递进）、(3) 深度盲区（不标定深度边界）。索引粒度必须足以回答"两本书在某主题上的方法论差异是什么？"。

### 索引文件格式

```markdown
# [源书名称] 深度知识索引

## 元数据（Metadata）
- 书名 / 作者 / 目标读者 / 前置知识假设
- 主要编程语言/框架版本 / 总章节数 / 代码示例总数（估算）

## 教学理念（Teaching Philosophy）
### 核心教学方法
[问题驱动 / 概念先行 / 示例引导 / 贯穿项目？2-3 句描述]
### 认知递进策略
[由简到繁 / 由底层到高层 / 由实践到理论 / 混合？]
### 叙事风格基线
- 叙事人称 / 句子长度 / 代码注释语言 / 术语引入风格（英文+中文/仅中文）
- 语调（正式/随意/对话式）/ 平均代码块长度（行）/ Sidebar 密度（每 N 行一个）
### 总体评估（集成视角）
- 在集成中的角色（主线/强化/专项/参考）/ 核心优势 / 核心局限 / 与其他源书的互补点

## 逐章深度分析（每章重复此结构）
### 第 N 章：[章节标题]
#### 内容覆盖
- 核心主题（按出现顺序）/ 主题权重 / 覆盖范围 / 段落结构（N 段 + M 代码块 + K 图/侧边栏）
#### 方法论分析
- 引入方式（问题/场景/定义/类比）/ 教学策略 / 认知递进 / 独特方法
#### 深度标定
- 深度等级（入门/中级/高级/专家）/ 讲解深度（仅 API？含原理/实现/边界？）
- 假设读者已知 / 本节未涉及 / 深度边界（在哪停、为什么）
#### 独特见解
- 本节独有见解 / 独特类比 / 独特示例 / 常见误解纠正
#### 代码示例清单
| 示例 | 行数 | 场景 | 可运行性 | 教学目的 |
#### 交叉引用
- 依赖前置章节 / 被后续章节引用 / 外部引用（文档/PEP/论文）
#### 风格特征
- 叙事密度 / 代码密度 / 练习 / Sidebar
#### 集成就绪度
- 推荐集成角色（主要/补充/侧边栏/参考）/ 集成注意事项 / 直接可用性（高/中/低）

## 跨章主题映射
### 主题 [A] 的递进路径
- 第 X 章：基础引入 → 第 Y 章：深入展开 → 第 Z 章：高级应用
- 递进模式
### 贯穿项目（如有跨章项目，描述其演进路径）

## 知识点交叉引用矩阵
| 知识点 | 章节 | 深度 | 前置知识 | 独特性评级 |

## 集成就绪度总结
- 本书能为集成贡献什么（3-5 句）/ 风格适配需求 / 已知风险 / 推荐集成策略
```

**行数估算**：每章 60-100 行；15 章书 ≈ 1100-1700 行，满足 >= 1000 行。

### 阅读证据要求（Phase 0 关卡自检）

每章"内容覆盖"必须含：精确段落数（非"大约 N 段"）、精确代码块数、>= 3 个具体技术术语（非标题改写）。

**索引深度自检**——能否回答：
```
□ 两本书在 [主题] 上的方法论差异？
□ 这本书在 [主题] 上讲到多深才停？
□ 这本书对 [主题] 处理的独特价值？
□ [概念 A] 和 [概念 B] 在本书如何关联？
□ 本书假设读者学 [主题] 前已知什么？
```
任一答不出 = 索引不够深。

**禁止**：仅从标题推断内容 / 连续两章证据格式相同 / "本章主要讲 X"式标题改写。

## Phase 1：架构评估

> 前置条件：Phase 0 所有知识索引已通过门控。

### 核心原则

- **架构是基于知识索引的分析，非目录拼接**。每章的存在、顺序、深度都有索引证据支撑。
- **章节骨架是教学设计，非大纲重排**。顺序服务认知依赖：概念基础 → 工具 → 项目 → 专题。
- **源书覆盖度双向检查**：仅证明"目标章节引用了某知识点"不够，还须反向检查每本源书章节/主题的处置（目标章节/侧边栏/附录/明确排除）。
- **不默认以最大/最权威书为骨架**。骨架选择由目标受众、学习路径、现代性、工程导向、章节依赖共同决定。
- **每章仅一个主要认知负荷**。一章含多个核心模型（资源/错误/并发/性能模型）应拆分。

### 工作项 1：跨书深度对比（子阶段 1.2）→ `cross-book-analysis.md`

#### 方法论差异分析
```markdown
### Topic: [Topic Name]
| Dimension | [Source A] | [Source B] | [Source C] | Integration Choice | Rationale |
|-----------|-----------|-----------|-----------|-------------------|-----------|
| Introduction style | [Problem-driven] | [Definition-first] | [Example-led] | [选哪个] | [为什么] |
| Teaching order | [A->B->C] | [B->A->C] | [C->A->B] | | |
| Depth target | [Introductory] | [Intermediate] | [Advanced] | [目标深度] | |
| Unique value | [X] | [Y] | [Z] | [如何用] | |
| Teaching quality | [High/Med/Low] | | | — | — |
```

#### 深度对齐分析
```markdown
### Depth Alignment Table
| Topic | [Source A] Depth | [Source B] Depth | Target Depth | Alignment Strategy |
```
对齐策略：**基础+深化**（浅书给框架、深书给进阶）/ **优势互补** / **独立视角**（保留为侧边栏）/ **重新设计**（都不满意）。

#### 边界互补分析
```markdown
### Boundary Complementarity Table
| Topic | [Source A] Boundary | [Source B] Boundary | Complementarity |
```

#### 风格冲突解决
```markdown
### Style Resolution Table
| Style Dimension | [Source A] | [Source B] | Unified Style | Resolution Method |
| 人称 / 术语 / 代码注释语言 / 代码块长度 | | | | |
```

### 工作项 2：目标目录设计（子阶段 1.3）

步骤：确定目标受众 → 确定主干来源（不一定某源书原目录）→ 按认知依赖排序 → 每章一个主要认知负荷 → 检查覆盖完整性。

```markdown
## Target TOC
### Chapter N: [Chapter Title]
- Capability objective（读完能做什么）/ Prerequisite concepts
- Primary cognitive load（仅一个）
- Source coverage：[Source A] Ch[X] 贡献 / [Source B] Ch[Y] 贡献
- Methodology choice（选哪本书的教法+为什么）/ Depth target
```

### 工作项 3：逐章整合计划（子阶段 1.4）→ `plan.md`

**每章计划必须自包含**——Phase 2 执行时不需重读其他文件（除非按需查索引特定章节）。

```markdown
## Chapter N Integration Plan
### Basic Information
- 标题 / 能力目标 / 前置概念（引用前章）/ 预估长度 / 预估代码示例数
### Source Mapping
| Source | Chapter | Role | Contributed Content | Usage Method |
| [Source A] | Ch[X] | Main narrative | [框架] | 取其教学路径和类比 |
| [Source B] | Ch[Y] | Reinforcement | [深度内容] | 补充原理和边界 |
| [Source C] | Ch[Z] | Reference | [实践建议] | 转为"常见陷阱"段落 |
### Methodology Choice
- 引入方式 / 教学策略 / 认知递进路径（各附索引证据）
### Depth Alignment Strategy
- 目标深度 / 各源内容（保持/深化/简化）/ 缺口内容（需新写）
### Content Synthesis Plan（逐小节）
#### [N.1 Section Title]
- 叙事来源 / 补充内容 / 新内容 / 代码示例（用哪个、是否改）/ 整合等级（L3/L4）
### Concept Bridging
- 与前章过渡 / 内部桥接 / 为后章铺垫
### Terminology Conventions
| English | Unified Translation | First Appears In |
### Style Baseline Example
[引用主书 1-2 段作为风格参考]
### Quality Expectations
- 知识点数 / 代码示例数 / 预估字数 / 预估整合标记数
```

### 源书画像维度（基于知识索引）

| 维度 | 检查来源 |
|---|---|
| 学习路径 / 概念深度 / 现代性 / 工程导向 / 代码密度 / 独特价值 / 排除风险 / 整合适配度 | 知识索引对应章节 |

### 目标目录自检

```
[ ] 每章只有一个主要认知负荷？
[ ] 每章有明确前置概念和能力产出？
[ ] 每个源书核心主题都已处置（正文/侧边栏/附录/排除）？
[ ] 基础模型建立前不引入进阶主题？
[ ] 有贯穿项目主线帮读者综合运用？
[ ] 工程实践放在可用位置，而非堆到末附录？
[ ] 记录了为何不采用某源书原目录？
[ ] 大纲/讲义/样章绝不标为"已完成书稿"？
[ ] 每章整合计划自包含？方法论选择有证据支撑？
[ ] 所有跨书方法论差异都做了分析并选定整合方式？
```

### 常见失败模式

| 失败模式 | 症状 | 修复 |
|---|---|---|
| 最大书偏差 | 默认以最大/权威书为骨架 | 先做跨书对比；由目标受众匹配度决定 |
| 覆盖度幻觉 | 只查目标知识点是否映射，未查源书章节遗漏 | 增加反向覆盖矩阵 |
| 粒度过粗 | 一章塞多个核心模型 | 按认知负荷拆章 |
| 缺项目主线 | 每章纯概念，读者不知如何综合运用 | 设计阶段项目/综合项目 |
| 过早完成 | 大纲/讲义被报为已完成书 | 标为架构草稿；禁标"已完成" |
| 专题污染 | 性能/并发/框架细节过早打断基础路径 | 拆为核心/支撑/进阶路径 |
| 空洞整合计划 | 只说"将 X 整合到 Y"无方法论 | 每个整合决策须有索引证据 |
| 缺风格解决 | 源书风格差异被忽略 | 必须完成风格冲突解决分析 |

### 输出：source-architecture.md（子阶段 1.6）

必须含：(1) 目标受众与场景（含明确超出范围）；(2) 逐书画像；(3) 跨书对比分析摘要；(4) 统一知识图谱（主题节点、前置依赖、下游能力、难度、实践产出）；(5) 目标目录；(6) 反向覆盖矩阵；(7) 排除/降级范围；(8) 骨架自检。
