# 多源：内容合成、整合纪律与门控（Phase 2-3）

> 供 generate-book 多源模式 Phase 2（章节生成）使用。本文件集中定义：合成方法论、整合级别、正确性/完整性/风格纪律、Coverage Guardian、以及各 Phase 门控（**全模式门控唯一定义处**）。

---

## 1. 知识堆叠 vs 教学叙事

多书集成最常见的错误：按序排列知识点加过渡句，就以为完成了。结果"事实正确但读起来像百科全书"——每个知识点都覆盖了，读者却形不成连贯心智模型。

**差异本质**：知识堆叠按"主题分类"组织；教学叙事按"问题驱动的认知递进"组织——每一节存在不是因为"这主题属于这里"，而是"理解上一节后读者自然提出一个问题，这一节回答它"。

```
堆叠：10.1 生成器基础 / 10.2 yield / 10.3 生成器表达式 / 10.4 itertools / 10.5 协程(突跳) ...
叙事：10.1 问题引入(10GB日志→OOM) / 10.2 生成器:函数→生产者 / 10.3 yield:暂停与恢复
      / 10.4 生成器表达式(回到10.1问题) / 10.5 桥梁:数据管道→协作调度 / 10.6 协程 ...
```

## 2. 章节叙事弧（三层）

**第一层·章节级弧线**：痛点 → 概念 A→B→C → 能力交付 → 闭环（用新能力重解开篇痛点）。

**第二层·节间桥接**：每节结尾为下节创造"但是……？"，下节回答。无自然"但是"=顺序有误/缺桥接段/主题不该同章。

| 节结尾 | 创造的"但是" | 下一节回答 |
|---|---|---|
| "生成器通过 yield 暂停执行" | "但 yield 只能产出数据吗？" | 协程：yield 的接收端 |
| "yield from 委托子生成器" | "但嵌套太复杂" | async/await 更简洁 |

**第三层·段内逻辑**：论点（陈述句开头）→ 论据（代码/推理）→ 意义（对读者意味着什么）。不要用"接下来，我们来看看 X"开头——那是堆叠标志。

## 3. 来源混合叙事合成

一节内容来自多源时，按优先级组织：
1. **主书取框架**（引入方式、类比、顺序）
2. **建议类书取实践**（条目式建议转为"常见陷阱/最佳实践"段落）
3. **入门书取简化解释**（作为"类比补充/初学者视角"侧边栏）
4. **官方文档取精确性**（API 签名、参数、版本差异）

**操作**：不要先写主书内容再粘贴建议。先写主书叙事框架 → 在叙事中找到"常见误解/易误用"的自然位置 → 以"你可能认为应这样写，但实际上……"融入建议（而非"EP 推荐 X"式脚注）。

### 插入内容的深度标定

非主书插入内容常是"浅层插入"（仅定义+示例）。用清单标定，缺则补：
```
□ 动机（读者为什么要学，非"因为第 X 章需要"）
□ 定义（用已知概念类比）□ 原理（解释底层机制，非黑箱）
□ 示例（实际场景，非玩具）□ 常见陷阱 □ 最佳实践
```
不允许浅层插入——要么完成教学链，要么不插入。

## 4. 示例演进与概念桥接

**连续示例 vs 独立示例**：集成书最佳策略——保留主书原示例为独立示例（不替换已验证好示例）；新增内容优先用连续示例（在主书示例同场景上叠加）。例：主书第 5 章用"书店库存"讲变量，第 9 章新增"字典推导"就用"书店库存"的字典推导版，而非全新"学生成绩"。

**示例质量标准**：可运行 / 自包含 / 有输出（注释展示结果）/ 真实场景（非 `foo="bar"`）/ 适当规模（3-15 行）/ 最少注释（仅"为什么"不明显时）。> 20 行需审查能否拆。

**概念桥接**：每个"插入 X 后插入 Y"序列，问"读者刚理解 X，能直接理解 Y 吗？不能则中间缺什么？"

| 概念 A | 概念 B | 缺少的桥接 |
|---|---|---|
| 闭包 | 装饰器 | 高阶函数/函数作为参数 |
| 生成器 | 协程 | yield 双重用途（产出+接收） |
| 类基础 | 元类 | 描述符/属性访问机制 |
| 同步代码 | async/await | 事件循环+协作调度 |

缺桥接则加 500-1500 字 + 1-2 示例。**跨章回引**：不只写"如第 6 章所述"，要用一句话提醒那个概念的关键要点。

## 5. 整合级别与 5 步改写法

| 级别 | 名称 | 操作 | 可接受？ |
|---|---|---|---|
| L1 | 直接插入 | 原样粘贴源内容 | ❌ |
| L2 | 风格适配 | 改写措辞，保留结构 | ❌ |
| L3 | 重组 | 重新设计结构，重写内容 | ✅ |
| L4 | 完全融合 | 从所有来源重新设计，无法辨识出处 | ✅ |

**Phase 2 输出必须达 L3 或 L4。**

**5 步改写法**：(1) 解构所有来源相关章节（提取概念、顺序、示例、类比）→ (2) 设计新结构（不用任何来源原目录，按读者认知组织）→ (3) 分配主/次来源（每小节一个主来源叙事，其他深度补充）→ (4) 以主干风格改写 → (5) 验证不可辨识性（随机抽 3 段测试读者能否看出处）。

**反模式**：

| 模式 | 问题 | 修复 |
|---|---|---|
| "我改写了措辞" | 结构未变，读者能看出 | 重组结构 |
| "我在主干之后添加了" | 主干与源内容间有明显接缝 | 交错穿插 |
| "我把所有来源分组了" | 每主题内风格切换 | 每小节只一个主来源 |

## 6. 正确性、完整性、风格纪律

### 正确性（验证等级）
验证等级 V1-V4 的定义与强制规则见 `shared/verification-levels.md`（严重/🟠 问题须 ≥ V2；API 存在/移除须 V1 或 V3；V4 须降级并标"未经验证"；集成新增代码须 ≥ V2）。

**代码验证 3 步**：(1) 块审查（import/API 名/参数签名）→ (2) 运行时（目标版本 API 跑代码块）→ (3) 版本（确认版本特定 API 与基线一致）。

| 陷阱 | 预防 |
|---|---|
| API 幻觉 | V1 运行时检查 |
| 版本时间线错误 | V3 查 What's New |
| Import 路径错误 | V1 运行时检查 |
| 参数偏移 | V1 或 V3 验证 |

### 完整性
- **覆盖度**（Phase 0-1）：每源 >= 80%，所有核心主题已覆盖，比例与篇幅匹配
- **映射**（Phase 1）：正向（每个 KB ID 映射到章节）+ 反向（每章对照所有源书）+ 缺口（每个缺口有添加/排除/延后决策）
- **输出**（Phase 2）：每个"插入"动作已执行、每个 sidebar 已加、每个已映射 KB 条目出现在输出、冲突已解、缺口已处理

### 风格一致性
**基线提取**：人称 / 句长 / 代码注释语言 / 术语引入方式 / 代码块大小 / Sidebar 密度 / 讲解深度 / 语调。

**来源适配**（规则：新内容适配主书风格，主书不适配新内容）：

| 来源类型 | 典型偏向 | 适配方式 |
|---|---|---|
| 深度教材 | 篇幅长、详尽 | 保留深度，精简措辞 |
| 建议类书 | 条目化、缺上下文 | 添加动机说明，合并相关条目 |
| 入门书 | 浅显简单 | 加深内容，升级示例 |
| 参考文档 | 干燥权威 | 添加类比、实践指导 |

**逐段落自检**（从非主源写完每段后，下一段前修正，不事后修补）：人称一致？句长 ±30% 内？术语遵循约定？代码块大小与基线一致？加了上下文过渡？语调一致？

## 7. Coverage Guardian（覆盖守护者）

**适用**：仅多源模式。

**底线规则**：
1. **每章**：某源被映射为"主要/次要"→ 该源在该章须贡献 >= 3 个整合标记
2. **每书**：总标记数 >= (该源被映射总章数 × 0.5)
3. **下限**：任何源书标记数不得少于全书总标记数的 10%（总标记 700 → 每源 >= 70）
4. **输出大小**：每章 >= max(各源同主题章节大小) × 0.8（防止集成书比单源书还少）

**补丁式检测**（任一命中即"补丁式"）：标记集中在 <= 2 章 / 标记从未作为小节首个标记 / 内容总在主源之后。

**检测时机**：每章关卡后（2.3）、批次检查后（2.5）、Phase 3 验证。**升级**：首次 = progress.md 记 WARNING；同源第二次 = 重写受影响章节。

```bash
python scripts/workflow.py generate-book <run_dir> coverage_report
python scripts/workflow.py generate-book <run_dir> coverage_guard
```

## 8. 质量感知检查清单（每章完成后，叠加在 G1-G8 之上）

**章节级**：开头有读者痛点/能力承诺？结尾有闭环？节间有自然"但是"桥接？无认知缺口？新增节覆盖完整教学链（动机→定义→原理→示例→陷阱→最佳实践）？
**段落级**：陈述句/问题开头（非"接下来"）？无 3+ 连续段落只陈述事实不解释"为什么"？示例有真实场景？建议融入叙事（非脚注）？
**读者体验自测**：模拟目标读者顺序读，每节结尾问"现在能做以前做不到的什么？自然想问的下一个问题是什么？下一节回答了吗？"——第三问答"否"则叙事弧有问题。

## 9. 门控（全模式唯一定义处）

**核心规则**：未通过 = 重写（Phase 2）或返工（Phase 0/1/3），不进入下一阶段。连续 2 章在同一关卡项未通过 → 停下检查 plan.md 是否有问题。

### Phase 0 关卡：知识索引
```
□ 每本源书有 index.md？每个 >= 1000 行？含所有必需章节（教学理念/逐章深度/跨章映射/集成就绪度）？
□ 每章有阅读证据（段落数/代码块数/具体术语）？无连续两章证据格式相同？
□ 无仅从标题推断的内容？
```
未通过 = 重新阅读补索引，不进 Phase 1。

### Phase 1 关卡：架构设计
```
□ source-architecture.md 含所有必需章节？
□ 跨书比较分析完成（方法论差异/深度对齐/边界互补/风格协调）？
□ 目标 TOC 每章只有一个主要认知负荷？反向覆盖矩阵 100%？
□ plan.md 每章有自包含整合计划（来源映射/方法论选择附证据/深度对齐/合成方式）？无 TBD/占位符？
□ 目标 TOC 自检全通过？
```
未通过 = 重新设计，不进 Phase 2。

### Phase 2 关卡：章节生成

**每章（2a）**：

| ID | 检查项 | 通过标准 | 未通过 |
|---|---|---|---|
| G1 | 覆盖度 | plan.md 所有 ID 都有标记 | 重写章节 |
| G2 | 代码质量 | 新代码有 V1-V3 标签 | 添加标签+验证 |
| G3 | 风格匹配 | 无翻译腔，与基线匹配 | 重写相关段 |
| G4 | 无重复 | 无重复说明 | 合并/交叉引用 |
| G5 | 叙事流畅 | 过渡自然，叙事弧完整 | 重写 |
| G6 | 深度匹配 | 符合计划深度目标，篇幅充足 | 扩展或精简 |
| G7 | 来源比例 | 每个已映射来源在该章 >= 3 标记 | 扩展来源贡献 |
| G8 | 输出大小 | >= max(源章节大小) × 0.8 | 扩展内容 |

**每批次（2b，每 5 章）**：

| ID | 检查项 | 通过标准 | 未通过 |
|---|---|---|---|
| G9 | 跨章一致性 | 术语一致，风格统一 | 修复该批次 |
| G10 | 来源不可辨识 | 随机抽 3 段无法辨别来源 | 重写 |

**全书（2c，所有章节完成后）**：

| ID | 检查项 | 通过标准 | 未通过 |
|---|---|---|---|
| G11 | 全局一致性 | 全书术语/风格/流畅度 | 修复 |
| G12 | 覆盖完整 | 100% 源材料已处理 | 补缺失 |
| G13 | 重采样检查 | 重对照 G1-G8 查 3 章 | 未通过则重写 |

**记录格式**（progress.md）：
```markdown
### Ch[N] 关卡
- 时间 / G1-G8 各项 通过/未通过—[证据] / 问题列表 / 动作：继续/重写
```

### Phase 3 关卡：验证
```
□ 覆盖度 >= 95%？全书术语一致？所有代码块可运行？所有交叉引用有效？
□ 章节间无风格跳跃？反向覆盖 100%？Coverage Guardian 无底线违规？
```

## 10. 不可辨识性测试（每章完成后）

```
□ 随机 3 段：能看出处？（否=通过）□ 术语一致？□ 叙事流畅？□ 深度一致？□ 示例同故事线？
```
记 progress.md：`ChN Source Test — Sample 3, Identifiable X/3 (目标 <=1/3), Terms/Flow/Depth pass/fail, Result pass/rewrite`。
