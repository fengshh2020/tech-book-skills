# 写作工艺：把「讲得透」操作化

> 正向工艺——怎么写**好**，不是怎么不写坏。红线（反冗余 / 反 AI 腔 / 铁律）在 `../../shared/writing-core.md`，本文件只讲正面怎么做。写作全程适用：动笔前读一遍，卡住时回来查对应节。

## 读者模型（动笔前，知识设计的输入）

设计结构**之前**先回答三个问题：

- 读者**已会什么**——可用的类比库（有嵌入式背景的读者，"事件循环"可类比中断向量；零基础不行）。
- 读者**会带着什么误解来**——给每个核心概念预判一个最可能的错误心智模型（"生成器就是惰性的列表"、"TCP 可靠所以消息不会乱序"）。
- 读者**读完要能做成什么**——可验证的能力，不是"了解 X"。

误解清单是后续所有讲解设计的靶子：**没打中任何误解的讲解，正确但无效**——读者读完仍带着原来的错误模型走人。

## 误解驱动讲解（每个核心概念下笔前）

先回答：读者此刻最可能的心智模型是什么？正确模型与它的分歧在哪一环？讲解就攻那一环：

1. **激活错误模型**——"直觉上，这里用 `list` 存也行——直到日志涨到 10GB"。
2. **让它撞墙**——显式的失败（OOM 报错、乱序的消息），不是断言"不行"。
3. **新概念作为修复登场**——它是墙的答案，不是清单里的下一项。
4. **回收对比**——"回头再看当初的想法，错在把'能遍历'当成'都在内存里'"。

反例：照定义展开、按正确顺序罗列——定义无误，但没打中任何人的困惑，等于没讲。

## 示例三件套（讲解链「示例 → 边界」两环的选法）

| 件 | 作用 | 要求 |
|---|---|---|
| 典型例 | 建直觉 | 最常见输入、真实值、可运行；拒绝 `foo`/`bar` 占位 |
| 边界例 | 划范围 | 空输入 / 极值 / 失败路径——一个边界例胜过一段抽象警告 |
| 反例 | 对照邻居 | 显式对照最易混的概念："它不是 X——X 才是…" |

- **worked example 随章演进**：同一个例子长出复杂度（第 2 章的 demo 在第 5 章加上错误处理与并发）——读者在熟悉上下文里只消化新概念。这是练习题的合法替代（练习题本身是反冗余红线）。
- 拒绝"单例 + 一句如上所示"。

## 能力弧（章的组织）

每章交付**一个能力**，不是知识清单：

- 开篇抛一个读者**当前解不了**的真实问题（不是动机宣言），全章讲解朝它去。
- 章末用新能力解掉开篇问题——能力收束，不是小结复述（那是红线）。
- 一节 = 一次完整的新认知：讲解链在节内闭合；相邻节新增概念 ≤2 个，超了就拆。
- **杠杆概念优先**：后续章节反复依赖、误解代价最重的概念分配最深讲解；边缘知识一句带过 + 给出处。深度不平均分配——平均分配是没做知识设计。

## 具体先于抽象（操作化）

- 抽象概念先给可触摸实例（代码 / 命令 / 真实数据），抽象作为"从这些例子里提炼"出场。
- 提炼完立即落一个**新**例子验证抽象——同例复用是复述，新例才是验证。
- 术语在直觉建立**之后**才命名——命名是收束，不是开路。
- 形式化定义 / 规范引用放机制讲完后，作为精确化的收笔。

## 可读性正向工艺

- **段落一个支点**：一段只推进一个想法；写完指不出支点句 = 拆。
- **句子节奏**：长短交替，连续三句等长 = 平，用短句收尾破掉。
- **标题即论点**："优先队列保证关键任务先出队"，不是"队列模块"——目录扫一遍就是全书的论纲。
- **过渡靠内容接力**：上节留下的问题在下节开头被接住；靠"接下来我们来看"是路标词（AI 腔结构 tell）。
- **每段有删不掉的信息**：一段删掉一半信息量不变，那段就是空转——要么写出只有这段在讲的东西，要么删。
