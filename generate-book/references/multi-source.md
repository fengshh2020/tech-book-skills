# 多源模式：深度阅读、整合架构与合成纪律

≥2 个源书时使用，产出**读者无法辨识来源**的整合书。读 `shared/writing-core.md`。两个跨阶段状态文件防丢上下文：`{RUN}/progress.md`（到了哪里）、`{RUN}/context-summary.md`（知道了什么，每子阶段追加 ≤150 行，下一阶段只读摘要 + 本参考）。

核心信念：**架构建立在深入理解之上，不是目录拼接**；**整合书按"问题驱动的认知递进"组织，不是知识点的分类堆叠**。

## Phase 0：深度知识索引

为每本源书生成深度索引 `{RUN}/knowledge_base/{book}/index.md`，粒度须能回答"两本书在某主题的方法论差异是什么？"（约每章 60-100 行，全书 ≈1000+ 行）。

每本索引含：**元数据**（书名/作者/目标读者/前置假设/语言版本/章节数）；**教学理念**（核心方法 / 认知递进 / 叙事风格基线：人称、句长、注释语言、术语引入、代码块长度、sidebar 密度 / 在集成中的角色与互补点）；**逐章深度分析**（内容覆盖：核心主题+权重+段落结构 `[N 段+M 代码块+K 图]`；方法论：引入方式/教学策略；深度标定：等级+讲解深度+假设已知+深度边界；独特见解；代码示例清单；集成就绪度）；**跨章主题映射**；**集成就绪度总结**。

**阅读证据**（关卡）：每章含精确段落数（非"约 N 段"）、精确代码块数、≥3 具体术语。**禁止**：仅从标题推断、连续两章证据格式相同、"本章主要讲 X"式改写。

**索引够深的判据**——能答出：两书在 [主题] 的方法论差异？本书在 [主题] 讲到多深才停？本书处理 [主题] 的独特价值？[概念 A] 与 [概念 B] 在本书如何关联？本书假设读者学 [主题] 前已知什么？答不出 = 补索引，不进 Phase 1。

## Phase 1：架构设计

完整读所有索引（不可略读），输出 `source-architecture.md` + `plan.md`：

1. **跨书对比**：方法论差异表（引入方式/教学顺序/深度目标/独特价值 × 各源 → 整合选择 + 理由）、深度对齐（基础+深化 / 优势互补 / 独立视角 / 重新设计）、边界互补、风格冲突解决（人称/术语/注释语言/代码块长度 → 统一基线）。
2. **目标目录**：按**认知依赖**排序（非某源原目录），每章一个主要认知负荷 + 能力目标 + 前置概念 + 源映射 + 方法论选择（附索引证据）+ 深度目标。不默认以最大/最权威书为骨架。
3. **逐章整合计划**（自包含——Phase 2 不重读其他文件）：源材料贡献图（主/次/参考）、合成策略、术语约定、风格基线样例（引用主书 1-2 段）。
4. **反向覆盖矩阵**：每个源章节 → 目标章节/侧边栏/附录/明确排除，100% 覆盖（只查"目标引用了某知识点"不够，须反向查每源章节的处置）。

**自检**：每章只有一个主要认知负荷？每源核心主题都已处置？基础模型建立前不引入进阶主题？有贯穿项目主线？工程实践在可用位置而非堆末附录？记录了为何不采用某源原目录？每章计划自包含、方法论选择有证据？

未过 = 重新设计，不进 Phase 2。

## Phase 2：章节合成（一次一章）

重读 `plan.md` 中该章计划，按**叙事弧**写——不是知识点堆叠：

- **章节弧**：痛点 → 概念 A→B→C → 能力交付 → 闭环（用新能力重解开篇痛点）。
- **节间桥接**：每节结尾为下节创造"但是……？"，下节回答。无自然"但是" = 顺序有误或主题不该同章。
- **段内逻辑**：论点（陈述句开头）→ 论据（代码/推理）→ 意义。不用"接下来我们来看 X"开头——那是堆叠标志。

**来源混合**：主书取框架（引入/类比/顺序）→ 建议类书取实践（转成"常见陷阱"段融入叙事，非脚注）→ 入门书取简化解释（作侧边栏）→ 官方文档取精确性。非主书插入内容须完成完整教学链（动机→定义→原理→示例→陷阱→最佳实践），禁浅层插入（仅定义+示例）。

**整合级别**（Phase 2 必须达 L3 或 L4）：

| 级别 | 操作 | 可接受 |
|---|---|---|
| L1 直接插入 | 原样粘贴源内容 | ❌ |
| L2 风格适配 | 改写措辞，保留结构 | ❌ |
| L3 重组 | 重新设计结构，重写内容 | ✅ |
| L4 完全融合 | 从所有来源重新设计，无法辨识出处 | ✅ |

**5 步改写法**：解构所有来源相关章节 → 设计新结构（不用任何源原目录）→ 分配主/次来源 → 以主干风格改写 → 验证不可辨识性（随机抽 3 段测读者能否看出处）。加标记 `<!-- integrated: [source]Ch[N]-[id] -->`。

**doc 形态**：整合完直接写就地 MD，轻量 gate（无 Coverage Guardian、无大小下限），但整合仍须 L3/L4、无翻译腔。
**book 形态**：`{RUN}/src/` 写 `book.yml` + `NN_*.md`，最后 `python scripts/build_html.py {RUN}/src {RUN}/output`。

## Coverage Guardian（仅多源，防一个源占 80%）

底线：① 每章某源被映射为主/次 → 该源在该章 ≥3 整合标记；② 每书总标记 ≥（被映射章数 × 0.5）；③ 任一源标记 ≥ 全书总标记 10%；④ 每章 ≥ max(各源同主题章大小) × 0.8。
**补丁式检测**（任一命中即判补丁式）：标记集中在 ≤2 章 / 标记从不作小节首个标记 / 内容总在主源之后。首次命中 → progress.md 记 WARNING；同源再犯 → 重写受影响章。

## 验证与自检

```bash
scripts/check_coverage.sh {RUN}/knowledge_base/ output/ summary   # 覆盖率 ≥95%
python ../shared/validate_tech.py output/; python ../shared/validate_terms.py output/
```

**每章自检**：非空、含 `<!-- integrated -->` 标记、无 `[待确认]`、大小 ≥ 最大源章 ×0.8、节间有"但是"桥接、随机 3 段无法辨识来源、术语一致、无 AI 腔（多源改写最易回归通用腔——刻意保留具体名词与确切动词）。
**全书自检**：覆盖率 ≥95%、反向覆盖 100%、Coverage Guardian 无底线违规、连续 3 章风格一致、交叉引用完整。

连续 2 章在同一项未通过 → 停下检查 `plan.md` 是否有问题，不累积修复。
