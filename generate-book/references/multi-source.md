# 多源整合：读透 → 统一结构 → 融合成一本书

≥2 个源书时使用。目标：读者拿到的是**一本**书——无法辨识哪部分来自哪本。读 `../../shared/writing-core.md`（讲解质量 / 反冗余 / 铁律）。

核心信念：**架构建立在深入理解之上，不是目录拼接**；**整合书按认知递进组织，不是知识点分类堆叠**。

## 读透每源

为每本源书在 `{RUN}/knowledge_base/{book}/` 存深读笔记（深度自定，喂 `scripts/check_coverage.sh`）。

**够深的判据**——能答出：
- 两本书在 [主题] 上的方法论差异是什么？各自讲到多深才停？
- 每本书的独特价值、引入方式、假设读者已知什么？
- 跨书对比：教学顺序 / 深度目标 / 风格（人称、术语、代码块长度）的差异 → 每主题取谁的长处、风格统一成哪条基线。

答不出 = 补读，不进下一步。

## 设计统一结构

完整读所有源笔记，产出目标目录（记进 `{RUN}/progress.md`）：

- 按**认知依赖**排序（先问题后概念、先具体后抽象），不默认以最大 / 最权威的书为骨架。
- 每章一个主要认知负荷 + 一个明确目的；基础概念建立前不引入进阶主题。
- **每个源章节都有处置**：进某章正文 / 降为侧边栏 / 进附录 / 明确排除（记录处置，这是覆盖率的来源）。

## 融合写作（一次一章）

写成**同一个作者**的一本书：

- 主源取框架（引入 / 类比 / 顺序），它源取实践（转成叙事里的"常见陷阱"段）或更简的解释——但**融合不豁免讲透**：任何插入内容都要走完整讲解链（动机 → 机制 → 示例 → 边界），禁止"仅定义 + 示例"的浅层插入。
- 沿叙事弧写：痛点 → 概念递进 → 能力交付 → 用新能力回解开篇痛点。节间衔接靠内容逻辑（上节留下的问题、下节回答），不靠"接下来我们来看 X"。
- **示例基线统一**：各源的例子换成同一条 worked example 线（随章演进长出复杂度）——保留各源洞见、丢弃各源例子的风格杂音（`craft.md` 示例三件套）。
- 讲解质量三标准与反冗余红线全程生效（writing-core）——整合时最容易犯的冗余是同一主题被多个源的内容各讲一遍；**判定主讲的源、讲透一次，其余源的增量融进那一处**。

**融合检验**：随机抽 3 段，读者看不出出处；一个源占 80% = 失败。章节加 `<!-- integrated: [source]Ch[N] -->` 标记（check_coverage 读它报告分布）。

## 覆盖率（客观兜底）

跑 `scripts/check_coverage.sh {RUN}/knowledge_base/ {RUN}/output/`（命令源见 writing-core 校验套件）。原则：每源章节都处置了、不能一个源占 80%。标记集中在 ≤2 章 = 补丁式整合，重写受影响章。

## 每章自检

节间衔接有内容逻辑、随机 3 段无法辨识来源、无同一主题多处主讲、术语一致、无 AI 腔（多源改写最易回归通用腔——刻意保留具体名词与确切动词）。连续 2 章在同一项未通过 → 停下检查结构，不累积修复。
